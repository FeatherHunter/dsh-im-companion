舰队雷达 · 7 场景验收

你要验收的是 「舰队雷达」（进法见准备工作第 3 步）：DSH 正中弹出的大弹窗里一张表，行 = 每个 Agent（一行就是一个助理），列 = 9 个 IM 渠道（飞书 / 微信 / QQ / Slack / Telegram / Discord / WhatsApp / 钉钉 / 企业微信），格子 = 该 Agent 在该渠道的机器人 LOGO + 状态。语言自动跟随 DSH 系统语言（中文 / 英文），没有手动开关。可打印本页逐项打勾。

0准备工作（必做，否则看到的可能是旧版本）
  1. 完全退出 DSH Desktop（托盘图标右键退出，不是点窗口 ×），再重新打开。
  2. 在 DSH 主界面按 Ctrl+F5 强制刷新一次。
  3. 打开 DSH 的设置页（齿轮图标），向下滚动，找到 「IM机器人辅助」 区域（Agent 列表那块）。看它顶部工具条：扬帆小船图标按钮与刷新按钮之间应有明显间距（约一个指甲盖宽，不挤在一起）；悬停小船显示「舰队雷达 Fleet Radar」。点击小船 → DSH 正中弹出大弹窗「舰队雷达」（配置面板原样留在后面）。关闭弹窗有三路：页头 × 关闭 / 按 Esc / 点弹窗外深色区——三路各试一次，都应回到列表。
没看到小船按钮？停下来，不要继续。说明新功能没加载成功。请截图设置页 + 记录这一步，然后按文末模板上报。

1入口切换与标题计数

目标

确认小船进、× 出通畅，大弹窗一次完整展示（无横向滚动条），标题和计数行正确。

步骤

  1. 确认左侧设置栏里 只有 1 个相关入口（IM机器人辅助），没有第二个「Fleet 矩阵总览」入口。
  2. 点小船，弹窗应在 DSH 正中打开（不是嵌在配置面板里），一眼能看到 9 列全表，没有横向滚动条。
  3. 读出雷达标题下一行的灰色小字，形如 3 个 Agent × 9 渠道 · 5 个机器人。
  4. 数一数表里实际的数据行数（不含表头），和"× 前面的数字"对比；数表头渠道列数（"Agent＼渠道"和"汇总"之间），应为 9 列。
  5. 确认页头右上角依次是 刷新、× 关闭（关闭在刷新右边）。点刷新一次，再点 × 关闭回到列表。
预期：弹窗居中、一次看全、无横滑；行数 = "N 个 Agent"的 N；渠道列 = 9；点刷新后不白屏不报错；× 正常关闭。
对抗检查：如果行数对不上，先等 20 秒再数一次（首轮 15 秒轮询可能还没到）。如果点刷新后整块消失或出现红色报错，直接记 fail——这是真 bug 信号。
2格子语义全覆盖

目标

把对照表里的每一种格子都在真表里找到一个实例（找不到某种就记下来，属于"无数据"而非失败）。

步骤

  1. 逐行扫表，对每种样子（在线 / 待确认 / 离线 / 未绑定虚线 / —）记下它在哪一行哪一列；确认表头 9 列每列都有彩色 LOGO + 文字，且格子里没有 LOGO（只有圆点 + 文字）。
  2. 把鼠标悬停在一个"在线"格上 1 秒，看浮动提示：应含渠道名、bot 编号、"点击钻取详情"。
  3. 悬停在一个"—"格上：提示应为"未接入，点击钻取详情"（空格点击同样开该行抽屉）。
  4. 看最右汇总列：挑一行，确认它的灯 = 该行所有格子里"最亮"的那盏（在线 > 待确认 > 离线）。
预期：提示文案与格子状态一致；汇总灯符合"取最亮"规则；"—"格是虚线灰框、不可误读为离线红灯。
对抗检查：最容易误判的是把"—"（没接入）当"离线"（接入了但掉了）——看颜色：灰虚线 vs 红灯，二者必须肉眼可分。如果某行明明有红灯、汇总却显示在线，记 fail。
3行排序（在线在上，未绑定沉底）

目标

确认行的排列遵守：已绑定的按健康排（在线 → 待确认 → 离线），未绑定的全部沉底，同档按名字排。

步骤

  1. 从上到下抄下每行的"汇总"状态 + 是否带"·未绑定"，记成一列（如：在线 / 在线 / 待确认 / 离线 / 在线·未绑定）。
  2. 检查：所有不带"·未绑定"的行，顺序是否为 在线→待确认→离线（允许缺档）。
  3. 检查：所有带"·未绑定"的行是否都在最底部（在线的未绑定也必须在离线已绑定之下）。
预期：两条都成立。如果你的环境里全是在线已绑定（很常见），只验证"按名字拼音/笔画有序"即可，在上报里注明"排序场景数据不足，只验了同档有序"。
对抗检查：这是数据依赖型场景——没有未绑定/离线数据时不要硬判失败。真正的 fail 信号只有一种：在数据齐全时顺序错乱（如离线排到了在线上面）。
4点格钻取抽屉（核心链路，连做 3 次）

目标

确认点击能跳到该行的 Agent 详情（C1a 抽屉），且三种点法都通。

步骤

  1. 记住第 1 行行首的 Agent 名字（如"小帅"）。点击该行任意一个"在线/离线"格 → 右侧应滑出详情抽屉，且抽屉里显示的是同一个名字。
  2. 用 Esc 关闭抽屉。点击同一行的一个"—"空格 → 同样应打开同一 Agent 的抽屉。
  3. 点击抽屉外深色区域关闭。直接点击行首的名字/头像区 → 同样应打开该行抽屉。
预期：三次打开的都是同一 Agent；抽屉可正常关闭，关闭后矩阵原样不动。
Fail 信号：点了没反应；打开的是别家 Agent 的详情；抽屉打不开还把矩阵卡死。出现任一即记 fail 并注明是第几次点击。
对抗检查：点"—"空格开抽屉是故意设计的（空格也属于该行），不要当成 bug 报。反过来，悬停提示必须和点击结果一致（提示"点击钻取"就必须真能钻）。
5空态与脚注交叉验证

目标

确认"没有数据时"和"表底小字"都是诚实的。

步骤

  1. 如果你的环境一个 Agent 都没有：应看到"还没有 Agent"空态图 + "新建 Agent 并接入任意渠道…"，且看不到空表头。有数据则跳过此条并注明。
  2. 读表底最后一行小字：要么是 9 渠道均有接入，要么是 某某、某某 暂无接入。
  3. 交叉验证：对小字里点名的每个渠道，纵向扫它整列——必须全列都是"—"；若小字说"均有接入"，则每一列至少有一个非"—"格。
预期：小字与整列实际完全对得上；空态不露空表头。
对抗检查：这是"自己证明自己"的断言，最容易藏谎报 bug——必须真的一列一列数，不要只看小字就打勾。
6窄屏：横滚 + 首列/表头冻结

目标

确认 9 列在窄窗口下不挤变形，而是横向滚动且首列钉住。

步骤

  1. 把 DSH 窗口拖窄（或把设置页侧栏拉宽挤它），直到表格底部出现横向滚动条。
  2. 拖动横向滚动条向右：第一列（Agent 名字列）应钉在原地不动，只有渠道列在走。
  3. 上下滚动页面：表头行（渠道名那一行）应吸顶，左上角"Agent＼渠道"角格在横滚时也不滑走。
  4. 把窗口拖回正常宽度，确认表格恢复、无错位残留。
预期：窄屏有横滚条、无文字挤叠；首列/表头/角格三处冻结；恢复宽度后正常。
Fail 信号：格子文字被压成多行/重叠；横滚时名字列跟着跑掉导致对不上行；恢复后表头错位。
7刷新稳定性 + 深浅主题跟随 + 系统语言跟随

目标

确认日常操作下不崩、主题切换不瞎、语言跟 DSH 走（没有手动开关）。

步骤

  1. 连续点 刷新 按钮 3 次（每次隔 2 秒）：面板不应白屏、不应报错、不应丢行。
  2. 去 DSH 设置里把主题切到深色模式：矩阵底色应变暗、文字仍清晰可读，格子颜色语义不变（绿仍是绿）。
  3. 切回浅色，确认恢复。
  4. 鼠标在一行上悬停：整行应有浅色高亮；悬停在格子按钮上：边框应变蓝。
  5. 去 DSH 设置里把显示语言切英文：保持雷达弹窗开着，看它是否在几秒内自动变成英文（标题 Fleet Radar、计数 3 agents × 9 channels · 5 bots、格子 Online/Pending/Offline/Unbound/Not connected）。若没自动变，关弹窗重进一次也算过（注明走了哪条）。
  6. 把 DSH 语言切回中文，雷达应自动变回中文。
预期：无白屏无报错；深色下无"黑字压黑底/白字压白底"；微交互（行高亮、按钮描蓝）正常；英文模式无中文残留（Agent 名字是用户数据，保持原样不算残留；QQ/Slack 等品牌名中英同形不算残留；页头没有中文/EN 开关——有开关就是没按新方案做的旧版本）。
对抗检查：深色模式重点看"—"虚线格和灰色小字——这两处最容易对比度不足。如果刷新后数字短暂闪动，那是轮询特性不是 bug；只有"行消失/报错/卡死"才算 fail。
