## Problem Statement

我有多个渠道机器人（飞书 / 微信 / QQ 等），而每一个工作区就是一个人（比如“小帅”）：机器人绑到哪个工作区，就变成谁，用谁的身份干活。现在每次分配身份都要逐个钻进抽屉改工作区：慢、易错、没有总览，批量上岗一批新渠道时尤其痛苦。

## Solution

在 Fleet 总览里把 Bot 行直接拖到左栏工作区行上，即完成绑定（分身份）。未绑定的直绑；已有所属的弹二次确认，确认后换绑；每次绑定成功都给 toast + 一段可撤销窗口；拖到空白处、放回原地等非法操作明确拒绝且不写坏任何东西。

## User Stories

1. 作为用户，我想把未绑定的 Bot 拖到某工作区行完成绑定，以便让它以上岗身份立即工作。
2. 作为用户，我想在悬停时一眼看出可放 / 冲突 / 不可放三种反馈，以便放手前就有预期。
3. 作为用户，我想把已有所属的 Bot 拖到别的工作区时看到二次确认，以便确认“挖人”是有意的。
4. 作为用户，我想在确认弹窗点取消后一切原样不动，以便反悔零成本。
5. 作为用户，我想在绑定成功后点 toast 撤销回到原状态，以便拖错时一键挽回。（修正见评论：新绑无撤销，仅换绑可撤销）
6. 作为用户，我想在撤销窗口过期后再点撤销会被明确拒绝，以便知道绑定已经落定。
7. 作为用户，我想把 Bot 拖到空白处时被拒绝且绑定关系不变，以便乱拖不闯祸。
8. 作为用户，我想把 Bot 放回它自己所在的工作区时什么都不发生，以便无惊吓。
9. 作为用户，我想在拖拽中途取消后一切回到原位无残留，以便试探零成本。
10. 作为用户，我想绑定写完后 Fleet 与左栏徽标即时刷新，以便所见即所得。
11. 作为用户，我想在身份配置不可用时拖拽入口被禁用并提示，而不是写坏已有配置，以便坏数据进不来。
12. 作为用户，我想连续把多个未绑定 Bot 逐个拖给不同工作区，以便批量上岗一次搞定。
13. 作为用户，我想每次操作后都清楚“刚才发生了什么”（绑定成功 / 换绑 / 被拒绝及原因），以便误操作可追溯。
14. 作为并行开发者，我想该功能可独立验证与整体移除（不碰其他功能目录），以便多线开发零摩擦。

## Implementation Decisions

- 功能自包含：单一功能模块，唯一对外入口为 manifest 挂载；功能之间禁止互相引用；只依赖共享层与 host 桥（单向依赖）。
- 状态机 lift 自 #13 原型 verdict：纯迁移（拿起 / 悬停 / 放下 / 确认 / 撤销 / 时间流逝），页面壳不进生产。经 grilling 定稿的迁移表如下（源自原型，可直接指导实现）：

  | 当前 | 动作 | 结果 |
  |---|---|---|
  | 未绑定 | 放到工作区行 | 直绑 + 普通 toast（新绑无撤销，见评论） |
  | 已属 A | 放到 B | 弹二次确认；确认→换绑 + 开撤销窗口；取消→不动 |
  | 任意 | 放到空白处 / 目标外 | 拒绝，绑定关系不变 |
  | 已属 A | 放回 A | 无操作 |
  | 拖拽中 | 取消 | 回原位，无残留状态 |
  | 撤销窗口开着 | 撤销 | 回滚到绑定前归属 |
  | 撤销窗口开着 | 时间流逝至过期 | 落定；此后撤销被拒绝 |

- 放置目标判定为纯函数（Bot 当前归属 + 目标 → 直绑 / 需确认 / 无操作 / 拒绝），与拖拽事件解耦。
- 拖拽源抽象为 Bot 行描述（标识 + 渠道 + 当前归属），不依赖具体 Fleet 控件 DOM；C1a 与未来矩阵各自派发同一动作复用该状态机。
- 写路径：经 dsh-im 渠道 RPC 落地归属（bot.workspace.set），写后触发唯一轮询源的手动刷新广播；不新开第二份轮询。
- 读路径：只经共享连接快照订阅与绑定选择器只读消费。
- 读不到真值时禁用写：身份配置不可用则拖拽入口禁用并提示（沿用抽屉“防覆盖”纪律）。
- 共享层只允许追加式改动；host 桥如需新端点只追加、按功能隔离命名；单文件规模红线不变。
- 撤销窗口精确时长由 #13 用户走查 verdict 定（原型演示用步进，真实现落为秒级）。

## Testing Decisions

- 好测试只测外部行为：给定绑定关系与动作序列，断言最终归属与用户可见结果（绑定成功 / 确认框打开 / toast 与撤销 / 原样不动），不断言内部状态形状。
- 落点为唯一的既有接缝：每功能自验证脚本（随 npm run verify 一起跑），覆盖上表全部迁移行；有视图断言需求时用仓库既有无 DOM 测试垫片。不新增任何测试 harness。
- 先验：左栏徽标、抽屉、左栏筛选三功能的既有自验证脚本即写法范本。
- 真机拖拽手感与冲突提示清晰度走人工验收（重启 → 拖拽 → 截图 → 用户点头），不自动化；#13 原型走查结论是验收输入。
- 可移除性：整体移出该功能后全检查（构建 / 类型 / 验证 / 行数红线）仍全绿。
