## Problem Statement

我是小帅这个工作区的主人，我想在我自己家里一眼看到我手下现在有哪些渠道机器人，顺手把不想留的换给别家，不用来回跑到机器人堆里去翻。机器人堆里领人很快，但日常管人时我只关心我这一屋，不想切来切去，换错还要能反悔，开除这种危险动作不要放在家里误点。

## Solution

在设置页的人名卡上加一段我这一屋的花名册：列全名下机器人（渠道加状态），每个可换给别家，换前弹二次确认，换后给可撤销窗口；左边行只留一个看一眼加跳过去管的小入口。只做看全加换家，不做开除，不做踢回大厅；同一本账的另一扇门，与 E2 不打架。

## User Stories

1. 作为工作区主人，我想在自己家看到名下全部机器人，以便不用去堆里一个个找。
2. 作为工作区主人，我想在名单里一眼看出每个机器人的渠道和在线状态，以便知道谁能干活。
3. 作为工作区主人，我想把名下一台机器人换给别家，以便人不合适时顺手转交。
4. 作为工作区主人，我想在换家前看到二次确认（从谁家到谁家），以便换家是有意的。
5. 作为工作区主人，我想在确认框点取消后一切原样不动，以便反悔零成本。
6. 作为工作区主人，我想在换家成功后点撤销回到原归属，以便换错一键挽回。
7. 作为工作区主人，我想在撤销窗口过期后再点撤销被明确拒绝，以便知道已经落定。
8. 作为工作区主人，我想在名下没有机器人时看到明确空态加去绑定的指引，而不是空白页，以便知道下一步去哪。
9. 作为工作区主人，我想在身份配置不可用时管的入口被禁用并提示，而不是写坏已有配置，以便坏数据进不来。
10. 作为工作区主人，我想换家写完后两边（设置页与左栏）即时刷新，以便所见即所得。
11. 作为工作区主人，我想在动手那一下系统先重查最新名单，过期就提示刷新再看，以便显示慢半拍时不瞎写。
12. 作为工作区主人，我想连续把名下多台机器人逐个换给不同人家，以便一次收拾完。
13. 作为工作区主人，我想在左边行看到一眼状态并能跳到家里管，以便路过能看、动手去大的地方。
14. 作为工作区主人，我不想在家里看到开除按钮，以便不会误点删机；开除仍走原来的地方。
15. 作为工作区主人，我想每次操作后都清楚刚才发生了什么（换家成功、已取消、被拒绝及原因），以便误操作可追溯。
16. 作为并行开发者，我想该功能可独立验证与整体移除而不碰其他功能目录，以便多线开发零摩擦。

## Implementation Decisions

- 功能自包含：单一功能模块，唯一对外入口挂载；功能之间禁止互相引用；只依赖共享层与 host 桥（单向依赖）。
- 主从形态：主力为设置页人名卡上的花名册段（名单全、确认框摆得下）；左边行只做只读入口（看一眼加跳过去管），不放表单与确认；详情抽屉不塞花名册（习惯管理地，保持可拆）。
- 只看加换家：看全名单；写只做换家（有家到别家），不做开除，不做踢回无主。开除继续走既有移除能力，不在本功能内另起第二种删除。
- 上游事实（grilling 已查实）：归属写入必须给非空绝对路径，空串被拒；有家回不到无主；既有解绑按钮走的是整机删除而非退回大厅。故本规格无退回大厅动作， undo 仅对换家有效。
- 放置判定复用 E2 verdict（源自拖拽原型，经 D1 grilling 确认沿用，纯判定表）：

  | 当前 | 动作 | 结果 |
  |---|---|---|
  | 名下有 A | 换给 B | 弹二次确认；确认换绑加开撤销窗口；取消不动 |
  | 名下有 A | 换回 A | 无操作 |
  | 名下为空 | 打开 | 空态加指引，不写任何东西 |
  | 撤销窗口开着 | 撤销 | 回滚到换家前归属 |
  | 撤销窗口开着 | 时间流逝至过期 | 落定；此后撤销被拒绝 |

- 读路径：只经共享连接快照订阅与绑定选择器只读消费，不新开第二份轮询；读不到真值时禁用写并提示。
- 写路径：经渠道归属写入落到目标绝对路径，写后触发唯一轮询源的手动刷新广播；动手前重查一次最新名单，过期提示刷新（单人场景下的防自己双窗口脏写）。
- 单人假设：无并发第二人，不做加锁与胜负裁决；最后一次写入自然为准，确认加撤销即足够。
- 撤销窗口沿用走查 verdict（秒级，演示与 E2 同口径）。
- 共享层只允许追加式改动；如需 host 桥新端点只追加、按功能隔离命名；单文件规模红线不变。

## Testing Decisions

- 好测试只测外部行为：给定归属与动作序列，断言最终归属与用户可见结果（名单、确认框、撤销、空态、原样不动），不断言内部状态形状。
- 落点为唯一的既有接缝：每功能自验证脚本（随 npm run verify 一起跑），覆盖上表全部判定行；有视图断言需求时用仓库既有无 DOM 测试垫片。不新增任何测试 harness。
- 先验：拖拽领养、抽屉、左栏徽标与筛选功能的既有自验证脚本即写法范本。
- 真机手感与文案走人工验收（重启加截图加用户点头），不自动化；#11 走查结论是验收输入。
- 可移除性：整体移出该功能后全检查（构建、类型、验证、行数红线）仍全绿。

## Out of Scope

- 踢回大厅（有家变无主）：需上游新接口，破不动上游边界，真需要另开票，不在本规格内。
- 开除（整机删除）：继续走既有移除能力，不在本功能内重复建设，更不在家里放第二种删除。
- 文件标记第二账本、改名改头像、健康聚合与着色规则变更。
- 详情抽屉内挂载花名册；矩阵视觉挂载（判定复用，挂载另行排期）。
- 触屏与无障碍点选兜底，留待验收反馈或另起票。

## Further Notes

- 核心心智（已与用户对齐定版）：工作区等于人（一对一），渠道机器人等于无身份躯壳，归属等于分身份；E2 是从堆里批量领人，D1 是在家里看全换家，只管谁归谁，不管渠道账号的创建与删除。
- 第一性备忘：B 为主 A 为入口的三条推出——地方大小（行里摆不下确认）、归属（左栏为本体地盘、设置页为自有地盘）、不与拖拽抢同一把手。
- 与 E2 关系：同一账本两扇门；E2 假设的直写路径成立，本规格落地后 E2 不需回炉。
