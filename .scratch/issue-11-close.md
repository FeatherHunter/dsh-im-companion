## 结论（grilling 定稿，2026-09-04，用户已认可）

### 目标

只做花名册管理：在 Workspace 一侧查看其名下有哪些 Bot，并可管理归属。不做改名改头像（身份自身设置，与 Binding 无关）。

### 边界

只走同一本账：写路径只走 dsh-im 渠道 bot.workspace.set，写后 stream.refresh，不直写 workspaces.json，不动 dsh-im 上游。不做文件标记（第二账本，出局）。1 Workspace = 1 Agent 硬约束不变。

### 风险

单人操作，无并发第二人。上游事实：workspace 必须非空绝对路径（空串被拒），有家回不到无主；现状解绑按钮走的是 bot.delete（整机删除，非退回大厅）。显示为 15s 轮询，动手前重查一次最新名单，过期提示刷新后重试，不瞎写；写后立刻刷新，换家给二次确认与 5s 撤销。

### 选项权衡

踢语义三选一：A 开除（bot.delete，现有点）B 换到别家（set 到另一绝对路径，可行）C 家里只看加换家。定稿 B+C：D1 只做看全加换家，不放开除，不碰踢回大厅。踢回大厅需上游新接口，超出本票边界，真需要另开票。

形态三选一：A 左边行 B 设置页大桌 C 详情抽屉。定稿 B 为主、A 为入口：B 地方大、为自有地盘、与 E2 拖拽把手不打架；A 只做看一眼加跳过去管；C 不做（习惯管理地，挤花名册难拆）。

### 决策

D1 = 设置页 Agent 卡上看全名下 Bot 并可换家（二次确认加撤销），左边行只留入口；同一 Binding 两面（E2 从堆里领人，D1 从家里换家），E2 假设的直写路径成立，不回炉。
