## Problem Statement

用户在配置面板里分不清“家 / 助理 / 机器人”三者：家（地点）会随工作区改名而乱、助理（人）会因机器人换号而丢改名史、头像以 dataURL 塞进元数据文件越撑越大、老数据（已有工作区 / 本地空壳 / 机器人绑定）没有确定的默认家归属。T4 原型与 T6 实现被这些未定语义卡住，不敢开工。

## Solution

把三者的身份、名字、头像、归属一次性锁死：家、助理各有独立稳定编号；名字“改过即冻结、没改过按链回落、可一键恢复默认”；头像“图存文件、元数据只存路径”；老数据按规范路径一区一家、空绑定与有名无区进暂存、不丢不自动复活。T4/T6 照此直接开工，不再返工。

## User Stories（28 条，验收对照源）

1. 作为家主，创建家时选已有工作区即绑定、不新建工作区，以便复用现有工作区。
2. 作为家主，创建家时选目录即新建工作区再落家，以便新地方有新家。
3. 作为家主，每个家有稳定编号、搬家（换工作区）后家还是同一个家，以便改名史和头像不丢。
4. 作为家主，工作区被删后家标为孤儿而不是消失，以便重选目录即可复活改名史。
5. 作为家主，未改名时家名自动等于工作区名，以便不用逐个起名。
6. 作为家主，工作区改名后未手改过的家名自动跟随，以便门牌不旧。
7. 作为家主，一旦手改过家名、后续工作区再改名也不跟随，以便命名权优先。
8. 作为家主，手改错后可以一键恢复默认，以便冻结不是绑架。
9. 作为家主，先建助理后绑机器人（助理独立存在），以便人先占位、号后到。
10. 作为家主，每个助理有稳定编号、机器人换号（删后重建）后助理还是同一个人，以便改名史不丢。
11. 作为家主，机器人被删后其助理标为孤儿而不是被删，以便换新号认领。
12. 作为家主，未改名且已绑机器人时助理名默认等于机器人名，以便人名片与号一致。
13. 作为家主，未绑机器人时助理名默认等于所属家名，以便空位也有可读名。
14. 作为家主，一旦手改过助理名、后续机器人/家改名也不跟随，以便人名权优先。
15. 作为家主，同工作区多个机器人各为一个助理、不合并，以便 A/B 号改名史互不覆盖。
16. 作为家主，上传家/助理头像后全端一致显示，以便一眼认出。
17. 作为家主，头像文件化后元数据不再膨胀、备份更快，以便老机器也不卡。
18. 作为家主，没设头像时看到首字默认图（同色同字稳定），以便未设置也有辨识度。
19. 作为家主，删家/换头像后的孤图被自动清理，以便磁盘不堆垃圾。
20. 作为老用户，升级后已有工作区自动一区一家（含无人之家），以便历史工作区不丢。
21. 作为老用户，已有本地空壳（有名无区）升级后进暂存而不是消失，以便旧名字可认领。
22. 作为老用户，未绑定工作区的机器人升级后进暂存而不是被丢弃，以便空号可后续落家。
23. 作为老用户，升级前自动备份、升级可重跑且结果稳定，以便失败可回滚、重跑不翻倍。
24. 作为老用户，已删工作区但仍被绑定指向的路径标为孤儿、不自动复活空壳，以便会话不回来时不骗我。
25. 作为家主，归档/置顶在升级后原样保留、不参与分组，以便整理不乱。
26. 作为开发者，“家/助理/机器人”术语全仓一致（旧 Agent 仅读兼容），以便新人不再猜。
27. 作为开发者，新旧命名共存期旧码不动、新表新名、映射层隔离，以便 T3 不膨胀成全仓重构。
28. 作为家主，在网页版真机上走完建家建助理绑机器人三级呈现，以便确认模型可用。

## Implementation Decisions

- 身份三权分立：家、助理、机器人各有独立主键；家主键与助理主键均为时间有序随机串（不由路径或机器人号派生，搬家/换号后身份存活）；展示排序可跟工作区序，身份连接只认 DSH 返回的规范路径。
- 家记录形状（决策态，不含存储细节）：家 = 编号 + 工作区标识（展示用）+ 规范路径（连接键，可空即孤儿）+ 名 + 名来源（用户手改 / 系统回落）+ 头像路径（文件相对路径，可空即默认图）+ 头像来源（用户 / 机器人 / 默认）+ 创建/更新时间 + 墓碑（解绑时间与原因，替代真删）。
- 助理记录形状：助理 = 编号 + 所属家编号 + 渠道（非空，单渠道语义）+ 机器人号（可空）+ 状态（未绑定 / 已绑 / 孤儿，一等状态）+ 名 + 名来源（用户 / 家 / 机器人）+ 头像路径 + 头像来源（用户 / 机器人 / 家 / 默认）+ 创建时间 + 绑定时间（可空）。
- 家命名链：用户手改 > 工作区标题（遇默认工作区做本地化）> 目录基名；旧路径键名只读兼容、不再写入。
- 助理命名链：用户手改 > 机器人名（已绑且非空）> 所属家名 > 缺省名；同工作区多机器人不合并、各立一助理。
- 冻结与恢复：名来源为用户后，工作区/家/机器人改名一律不跟；设置页提供“恢复默认”将来源打回系统/家/机器人并更新时间；家改名只推送给来源为家的助理。
- 头像策略（已定“图存文件、元数据只存路径”）：内容寻址命名（哈希 + 展示用小图双码率，WebP），元数据存相对路径与校验；源文件上限沿客户端现有门槛（不跟宿主大门限），超限降质不拒收；默认图为代码内联首字（同色同字稳定）；孤图延迟清理（删家时登记、下次启动清）。
- 迁移策略：升级前备份元数据；版本号升至 2 并新增家表与助理表，旧名字/头像/空壳字段封存只读；以规范路径为幂等键（DSH 返回为准回写，自拼只读容错）；DSH 全集一区一家；非空归属机器人各一已绑助理；空归属机器人各一未绑定助理进暂存家；有名无区空壳进暂存；归档/置顶原样保留；悬空路径生成墓碑家、不自动新建复活；默认工作区不特殊命名。
- 术语策略：Agent 退役为遗留别名（家与其下助理集合，仅读兼容）；契约只用家/助理/机器人；新表新名、旧码不动、映射层隔离；本规格顺带更新领域词汇表一行与契约一条，不做全仓重命名。
- 原子性边界：跨系统三步（新建工作区 + 家落盘 + 机器人归属）无事务，本规格只要求幂等 + 孤儿态，对账重试归实现票。

## Testing Decisions

- 好测试只断言外部行为：给定绑定关系与动作，断言用户可见结论（展示名、分组、孤儿态、迁移后家单），不断言内部字段名与存储形状。
- 测三块：命名回落解析（含冻结与恢复默认）、分组与孤儿判定、老数据迁移（幂等可重跑、暂存不丢、悬空标孤儿、备份存在）。
- 新纯逻辑模块是唯一主缝（理想单缝）：命名 + 分组 + 迁移三个纯函数同一模块，宿主落盘与机器人归属只做薄封装；先行证据为既有 adopt 自验证（纯逻辑 node --test）与宿主入口验证（装配与信封断言）。

## Out of Scope（已否决或归实现票）

- 一个家管多个工作区；一助理绑多机器人（均已否决）。
- 宿主定时调度器去留；搬家以助理为单位的失败回滚与多端刷新语义（归实现票）。
- 创建家后是否自动打开工作区/建空白会话；本机选择器实际分支确认（归真机票）。
- 桌面版真机验收（本次只验网页版）；上游更新包本身的改动（跨仓）。
- 全仓旧 Agent 命名重构（本规格只做新表新名 + 映射隔离）。

## 输入与风险

- 输入：T1 取证（工作区四层链、选区只写本插件、新建权威调用、规范路径一区一家）与本次 grilling 结论（#108 正文 Q1–Q6 架构师版，用户 2026-10-08 已认可）。
- 风险：跨系统非原子中间态；规范路径口径（大小写/斜杠/symlink，Windows 重灾区）；多机器人同区不合并。
