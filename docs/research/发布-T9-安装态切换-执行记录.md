## 二、安装态切换（link → 按版本号）

目标态：profile 依赖写精确版本号 `0.1.8`，安装落点**不再指向本仓**——这是更新包判 `sourceInstall` 的判据（判据用 `realpath`，**不要求 LinkType 为空**：pnpm 正常安装自己也会留一层链接，只要它不是指向源码仓）。

命令：

```bash
dsh plugin --profile web add --save-exact dsh-im-companion@0.1.8 --registry=https://registry.npmjs.org
```

**真机坑（必记）**：宿主正在运行时直接跑这条**必挂**：

```
[ERR_PNPM_EPERM] [importPackage ...] EPERM: operation not permitted,
rename '...\node_modules\dsh-im-companion_tmp_45236_11' -> '...\node_modules\dsh-im-companion'
```

成因：pnpm 用 `rename` 覆盖既有入口，而该入口此刻是个**指向本仓的 Junction**。**解法 = 先删掉那个 Junction 再装**（删重解析点不动本仓，实测本仓文件完好）：

```powershell
[System.IO.Directory]::Delete("$env:USERPROFILE\.dsh\profiles\web\node_modules\dsh-im-companion", $false)
```

> 不要用 `Remove-Item -Recurse` 干这件事。`Delete(path, recursive:false)` 只摘链接本身。
> 用同一个草稿工程（无宿主参与）跑同样的 link → 版本号 切换是**成功**的，故 EPERM 属宿主占用/覆盖语义，而非 pnpm 通病。

备份（切换前）：`package.json.bak-t9-20260912-202913`、`pnpm-lock.yaml.bak-t9-20260912-202913`（两份都备，缺锁文件会让回滚白做）。

改前 → 改后对账（全部实测）：

| 项 | 改前 | 改后 |
|---|---|---|
| `dsh.profile.bundles` 项数 | 18 | 18 |
| profile `node_modules` 顶层项数 | 242 | 242 |
| 六个 `link:` 插件（bill/calorie/chef/home/memo/schedule） | Junction 指向 `D:\ilife\...` | **原样** |
| `dsh-mattpocock-skills-deck` | 1.7.20 | 1.7.20 |
| `dsh-im-companion` 依赖声明 | `link:D:/dsh-plugin/dsh-im-companion` | **`0.1.8`** |
| 安装落点 | Junction → 本仓 | 真目录（非本仓） |
| `lib/index.js` / `lib/client.js` SHA256 | 与本仓一致 | **与本仓一致**（`86D8D886…` / `7CE2AE72…`） |

> 发布用的那次失败尝试曾把 profile 的 `pnpm-lock.yaml` 写脏、并把 deck 升到 1.7.21；已用备份还原，第二次安装后 deck 回到 1.7.20，`pnpm list --depth 0` 顶层显示 `dsh-im-companion 0.1.8`。

## 三、回滚手册（改回 link）

前提：① 若宿主在跑，**先由项目负责人停掉**（占用会 EPERM）；② 重启由负责人本人完成；③ **回滚本身不需要重启**——它只修磁盘状态，宿主半留到下一次自然重启生效。

1. 还原两份文件（取该时间戳那对，别用通配）：
   `package.json` ← `package.json.bak-t9-20260912-202913`；`pnpm-lock.yaml` ← `pnpm-lock.yaml.bak-t9-20260912-202913`
2. 清掉按版本号装的那份真目录，再重建 Junction：
   `[System.IO.Directory]::Delete(<profile>\node_modules\dsh-im-companion, $false)` → `New-Item -ItemType Junction -Path <profile>\node_modules\dsh-im-companion -Target D:\dsh-plugin\dsh-im-companion`
3. 对账：bundles 仍 18；六个 `link:` 插件仍在；`lib/client.js` hash 与本仓一致。
4. 改回后的**预期表现**：更新区显示「当前是从源码安装的」（`source-install`），**不给安装按钮、也不给手工命令**——这是诚实设计，不是故障。
