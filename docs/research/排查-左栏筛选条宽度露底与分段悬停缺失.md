# 排查-左栏筛选条宽度露底与分段悬停缺失（BUG 建单取证 · 2026-10-21）

> 用途：新建 BUG 票的前置取证（先查后问）。结论先行，所有判断附仓内行号或运行时原文；本文件不含实施，票面只建单。
> 关联票：#159（https://github.com/FeatherHunter/dsh-im-companion/issues/159）。「实际/期望/复现/环境」四项来自报告人原话整理。

## 结论（两处独立缺陷，落在同一处 UI）

1. **宽度露底 = 条带 360px 封顶 vs 侧栏可拖到 420px。** sticky 覆盖层只有 360px 宽且有实色背景；侧栏内容宽 >360 时左右各留 (内容宽−360)/2 的空白带，滚动列表的行从带里露出。360 不是设计宽度，是 #48 的安全垫（票面原话「条带 `max-width:360px`，锚错也不撑满全屏」）；#94 之后容器已改结构优先（`role="tree"`），安全垫仍在，但侧栏上限已到 420。
2. **悬停缺失 = 唯一的分段 hover/active 规则装在设置面板命名空间里。** 基表 `theme.ts` 没有 `:hover`；补丁只在 `first-view-styles.ts`，只由 `panel.ts`（设置面板）安装/卸载；启动期 `FEATURES` 循环不装 first-view ⇒ 左栏（首页）永远拿不到。owner 2026-10-17 指令「所有可点控件都要让人在悬停/点击时感到交互」在这处未被覆盖。

## 证据（一手）

### A. 宽度露底

- `src/features/left-filter/styles.ts:5` — `.left-filter-strip{position:sticky;top:0;z-index:5;box-sizing:border-box;width:100%;max-width:360px;margin:0 auto 2px;padding:6px 0 8px;overflow:hidden;display:flex;align-items:center;gap:6px;background:var(--dsw-specific-sidebar-fill,transparent);…}`：只有 360px 自身的盒有背景，两侧带没有遮挡。
- #48（closed 2026-09-07，票面「左栏筛选条首装全宽置顶故障记录」）修复清单第 3 条：「样式封顶：条带 max-width:360px，锚错也不撑满全屏」；同票记录条带是 DOM 直插（宿主无 `workspace-rail` 槽位）、容器靠启发式反推，且加了 >380px 容器验货 fail-closed。
- `src/features/left-filter/dom-scope.ts:61-87` — #94 之后容器判定改为官方列表容器（`role="tree"`）优先；条带插入前的容器验货见 `src/features/left-filter/view.ts` 的 `containerOk`。
- DSH 运行时原文（`D:/DeepseekHarness/resources/app.asar`，node 直接检索）：`function computeColumns(viewport, sidebar, rightbar, collapsedWidth = 56){ const s = sidebar === 0 ? collapsedWidth : clampWidth(sidebar, 264, 420); … }`；`sidebarPreference = … layoutInfo.sidebar === 0 ? 280 : layoutInfo.sidebar` ⇒ 侧栏宽域 264–420px、默认 280px。360 < 420 ⇒ 拖到上限必现。
- 报告人截图实测（732×192，150% 缩放）：侧栏约 420 CSS px；条带 360 ⇒ 每侧约 30 CSS px 空白带；左侧带内可见列表文字残影（`u` 片段 device x≈30–40）。

### B. 悬停缺失

- `src/client/theme.ts:70-76` — `.af-seg-item{…color:var(--af-secondary);cursor:pointer;transition:color .15s}`；只有 `.active` 与 `:focus-visible`，没有 `:hover` / `:active`。
- `src/client/components/first-view-styles.ts:106-115` — 段落标题「交互反馈补全（owner 2026-10-17：所有可点控件都要让人在悬停/点击时感到交互）」；注释自述补的缺口之一是「② 悬停都没有（分段 tab）」；规则 `.af-seg-item:not(.active):hover{color:var(--af-primary)}`、`.af-seg-item:active{transform:scale(.96)}`。
- 安装路径：`first-view-styles.ts:128-131` 的 `installFirstViewStyles()` → `installFeatureStyles('first-view', …)`；唯一调用点 `src/client/components/panel.ts:52`（FleetPanel＝设置面板挂载时；随返回的 dispose 在卸载时清理）。
- 启动期：`src/client/index.ts:76-84` 只对 `FEATURES` 逐个 `f.installStyles()`；first-view 不在 FEATURES（其样式由 panel.ts 装）⇒ 左栏首页没有 `af-seg-item:hover` 规则。
- 左栏自有样式只有两个图标钮有 hover：`src/features/left-filter/styles.ts:15`（`.left-filter-hbtn:hover`）、`:19`（`.left-filter-collapse:hover`）；三个分段无 hover/active —— 与截图「同条带绿点/收起有反馈、分段没有」一致。
- 原型阶段未设计过：`prototypes/left-filter/prototype-b2-left-filter.html` 的 `.dsb-filter button` 无 hover（只有行/会话/图标钮有）⇒ 属 2026-10-17 补全时的遗漏，不是回归。

## 复现条件

- 宽度：侧栏内容宽 >360px（拖宽到 361–420 区间）；默认 280px 下推断看不到。
- 悬停：任意宽度必现；不需要打开设置面板，且只要不打开设置面板就恒无（打开设置面板期间会被装上、离开即清理——推断，待真机复核，可作反证细节）。

## 影响

- 视觉：滚动时内容从条带两侧漏出，像「条带没盖住」；报告人截图即证据。
- 交互：三个 tab 无悬停/按下反馈，违反 owner 2026-10-17 指令；与同条带的两个图标钮不一致（那两处有 hover 背景）——用户会以为不可点。

## 修复方向（供下令，本票不实施）

1. 宽度：去掉 360 封顶、条带随容器满宽；安全性交给 #48/#94 已有的容器验货 fail-closed（混入头栏按钮或超宽 → 摘条带）。或保留内容宽上限、另铺一层全宽背景（两层结构）。两种都要保 #48 首装全宽回归用例。
2. 悬停：把 `.af-seg-item:not(.active):hover` / `:active` 放进启动期必装的命名空间（放 left-filter 自有 CSS 最顺；`theme.ts` 已 300 行红线不能再加），或把 first-view 这段改为启动期全局安装。
3. 回归面：`tools/verify/features/left-filter.ts`（宽度/容器验货/#48 回归）、相关 verify 与 `npm run check`；宽度至少过 264/280/360/380/420 五档。

## 待查 / 边界

- 侧栏 361/380/400/420 逐档实测带宽度，验证 (w−360)/2 公式；并确认默认 280 下完全看不到。
- `isPlausibleWorkspaceHeader` 残留绝对宽度窗 120–400px（#94 票面「已知遗留」）：侧栏 >400px 时**漏斗**缺席，与条带无关但同属「侧栏变宽」类，修宽度时顺手复核是否随 420 上限一起放宽。
- 设置面板打开时左栏 hover 是否「临时出现」（CSS 无作用域，推断会）——复核后可作为根因的反证细节。
