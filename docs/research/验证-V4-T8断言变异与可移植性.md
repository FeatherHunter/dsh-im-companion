## 黑名单断言真伪裁定

**半真：不是永远通过的空转，但对作者指定的 M3 形态（副作用式 `import 'pkg'`）无效。**

- 活着的证据：宿主侧正向对照必须命中（`src/host/update.ts`）、`files.length >= 8` 与 `sources.length > 20` 两个下限门、M3b 能红 ⇒ 检测器确实在跑。
- 漏洞证据：M3c 全绿。bare 引入不匹配 `/(?:from|require\s*\(|import\s*\()\s*['"]dsh-plugin-update/`（`import` 后面没括号、也没 `from`）。
- 次要弱点：`lib/client.js.map` 不存在时产物分支走 `else if`，bundle 也不存在时**整条产物检查静默跳过**（fresh clone 未 build 时 T8-12 只剩源码扫描）。
- 建议修法：正则补 `import\s*['"]…`（或分开一条 `^import\s*['"]` 的裸引入检测）；产物分支改成「map 与 bundle 都不存在 ⇒ 断言失败」。
- 另注：M3a 之所以全文件崩，是 harness 把 `constants.ts` 编译进 `OUT` 后 `OUT` 下没有 `node_modules` 上溯链 —— 那是**意外红**（不是断言红），恰好掩盖了 M3c 那个漏抓。

## 可移植性核实

- **无绝对路径、无本仓外路径**：改动里所有 `node_modules` 引用共 4 处，全是 `join(REPO, 'node_modules', …)`（`update-center.ts:12,24,49,53`；`update-host.ts:15,18,26` 同款），`REPO = process.cwd()`；
  全仓扫描 `tools/`、`src/`、`scripts/`、根 `*.json` 未命中盘符绝对路径或固定用户名目录；`first-view.ts:49` 的 `Dsh-mattpocock-skills-deck` 只是产品文案字符串，非路径（#80 先例未被重犯）。
- **依赖全部来自本仓**：`--typeRoots <REPO>/node_modules/@types --types node` 指向本仓自己的 `@types/node`（devDependencies 已声明 26.4.1）；tsc 走 `join(REPO,'node_modules','typescript','bin','tsc')`（devDependencies 7.0.2）；
  `dsh-plugin-update@0.1.1` 在 dependencies；`package-lock.json` 已入库 ⇒ `git clone && npm install` 即可，无全局工具、无 `npx` 现场下载。
- **无临时/机器状态依赖**：verify 链不联网（T8-11 全部注入 `fetchImpl`、T7 用假 npm 源）；临时物只经 `mkdtempSync(tmpdir())` 并在 `after()` 清理；环境变量只有可选 `GUARD_LIMIT`（默认 300）与产品级 `DSH_HOME`；
  `guard/check-lines.ts:16` 用 `import.meta.url` 定位仓库（不依赖 cwd），其余脚本用 `process.cwd()`（约定：从仓库根跑 `npm run check`，与 `render-client.ts:10` 注释一致）。

  整条 `npm run check`（build → typecheck → verify → guard）**exit 0**，T8 16 例全绿，`guard: 116 files, max 300 lines, limit 300 — PASS`。
