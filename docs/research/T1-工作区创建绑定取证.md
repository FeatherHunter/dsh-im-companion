## 1. 工作区列表真实来源（四层链）

### 1.1 磁盘：storages/workspace.json（domain workspace v2）

- 顶层三段：unit{name:workspace,version:2} ＋ global{initialized,defaultWorkspaceId,workspaceIds[],archivedSessionIds[],pinnedSessionIds[]} ＋ tables.workspaces{id→{path,title,sessionIds[],createdAt,updatedAt}}。实盘已验（见附录 A）。
- 持久化契约：dsh-workspace/lib/types/spec.js:46-69（workspaceDomainSpec：workspaces 表＋workspaceIds 为权威展示序，归档/置顶为会话 id 数组，defaultWorkspaceId 首用身份，pendingMutation 双写标记）。
- path 是 fs.realpath canon（paths.js:43-48）：存的是规范化路径，唯一性＝规范串相等（symlink 指到已占目录即撞车）；sessionIds 是归属账本（spec.js:18-24）。

### 1.2 宿主：ctx.workspaceRegistry ＋ ctx.workspaceController（Remote 命名空间 workspace）

- web profile 装配实测（dsh --profile web --dump-config，只读）：含 workspace（dsh-workspace）、directory-picker（dsh-host-directory-picker-auto，自适应）、workspace-controller（dsh-api-workspace-controller）、ui-workspace（dsh-client-ui-workspace）。
- WorkspaceController：static inject = typer+workspaceRegistry，super(ctx, workspaceController, {namespace: workspace})（lib/types/index.js:85-99；展包 lib/index.js:853 同式）。Remote 动词：create/initializeDefault/rename/delete/insertBefore/insertSessionBefore/archiveSession/unarchiveSession/pinSession/unpinSession/follow(stream)（lib/types/index.js:61-82）。

### 1.3 客户端：workspaces 服务 ＋ uiWorkspace 服务

- WorkspaceController 客户端：super(ctx, workspaces)，this.list = model（lib/client.js:388-392）。ClientWorkspaceModel.create(input) 调 remote.create，成功即合并 unary 回声；getSnapshot() = {items,archivedSessionIds,pinnedSessionIds,state,phase,error}（lib/client.js:51-55,255-268）。竞态规则：新行以 updatedAt 赢、已提交的 stream 序压过旧 unary 回声、删掉的 id 不许被迟到数据复活（lib/client.js:287-312）。

## 2. 选已有区绑定的写入位置与接口

### 2.1 关键否定事实：选已有区不调任何 DSH 工作区写入

- DSH 侧家是个插件自有概念，注册表里没有家的字段（workspaceRecord 只有 path/title/sessionIds/createdAt/updatedAt，spec.js:18-24）。选已有区＝新建家记录指向已存在 workspaceId，DSH 零调用。
- 反证：本仓 src 内 workspaces.create|remote.workspace|initializeDefault 零命中（grep 实测），今天所有选家动作都只写自家账本或 dsh-im。

### 2.2 家侧写入：本插件 meta.json ＋自有桥

- 文件：path.join(dshHome, integrations, dsh-im-companion, meta.json)（src/index.ts:30；meta-store.ts:1 注释同）。形状 AgentMetaDoc{version:1,names,avatars,locals[],presets,ctxEnhance,welcomed,update,motion}（meta-store.ts:29-43）。
- 家即工作区全路径键：names[workspacePath]、avatars[workspacePath]（读兼容旧 basename 键，新键优先＋归一化兜底，model.ts:80-105）；本地空壳 locals[{name,workspace}]（meta-store.ts:163-199）。
- 桥：channel /im-companion（meta.ts:205），RpcMetaStore → meta.get/meta.rename/meta.avatar.set|clear/meta.local.add|remove|rename/meta.local.workspace/meta.preset.set/meta.ctx.set/meta.welcomed.set（meta.ts:49-100；宿主分发 host/rpc.ts:62-198）。校验失败回 bad-request，本仓侧超时 5s（meta.ts:54）。

## 3. 选目录触发新建工作区的调用与失败形态

### 3.1 官方调用链（Add workspace 标准动作，本仓 T6 照抄）

- 步骤1 目录选择：uiWorkspace.pickDirectory() → directoryPicker.pick()（native OS chooser；取消→null；见 §3.4），或 browse：directoryPicker.list(path)/createDirectory(path,name)（远端/无 OS 弹窗时）。
- 步骤2 收养：adoptDirectory(path) → workspaces.create({path}) → remote.workspace.create → WorkspaceCommands.create：先 resolveByPath(path)，已存在→{workspace, created:false}（幂等，官方 README:53）；不存在→registry.create(path)→realpath canon→双写提交→{workspace, created:true}。
- 步骤3 选中：列表投影刷新后才选中提交项（ui-workspace/README.md:92-94）。
- 触发与收养是洞＋occupant对话：conversation.hero.workspace.directoryFlow / sidebar.workspaces.directoryFlow（single kind），occupant 每次 open 上升沿跑一次 pick，上报一个结果（open/busy/onPicked/onCancel/onError）；owner 置 busy hold 住洞直到 Host 应答（ui-workspace/README.md:92-94；native 侧 NativeDirectoryFlow armed-once 语义，directory-picker-native/lib/client.js:34-49）。
- create 客户端面：workspaces.create(input) 成功合并 unary，失败抛 WorkspaceCreateError（带 .rpcError，lib/client.js:356-397）。
- 本仓原生优先、内置兜底已就绪：nativePicker/direct→get透传（dir-picker.ts:19-51），native 抛错非取消类→回退 openHostBrowser（走自有桥 fs.list/fs.roots/fs.defaultRoot，dir-picker.ts:61-90,147-220）。缺的是 create 这一步（§2.1 反证）。

### 3.2 路径校验（建之前就知道会不会炸）

- 必须完全限定：POSIX 以 / 起；Windows 要 isAbsolute 且根不是裸反斜杠或斜杠（paths.js:14-19）。盘符相对、根、普通文件一律拒收（注册表 README:53）。
- 规范化走 fs.realpath：尾杠、..、symlink 全解；不存在的路径在 realpath 处以原始 ENOENT 拒绝——这就是 create 的拒绝路径（工作区必须指向已存在目录）（paths.js:31-48）。
- 同 canon 已被占→不报错，直接返回现有一项（commands.js:18-34）。

### 3.3 首用默认家（initializeDefault，只读备忘）

- 空注册表＋无 live/持久/归档会话（含无 cwd 会话）才够格；在 mutation 队列里解 Documents 目录、建缺失父目录、canon 后复查历史再提交；成功一次即记 defaultWorkspaceId，以后只返回不再解目录；删掉它也不再自动建（注册表 README:62-69）。插件侧不应在创建家时调用它（startup 专属）。

### 3.4 稳定错误码表（wire 契约，调用方只判码不抠字串）

| 码 | 产地 | 含义 |
|---|---|---|
| workspace/invalid-path | commands.js:31 | 相对路径／盘符相对／缺失／是文件／canon 失败，带 {path} |
| workspace/name-conflict | commands.js:49 | 改名撞名（判重排除目标自身 id） |
| workspace/not-found | commands.js:188 | id 不存在（删/排/移的目标） |
| workspace/move-invalid | commands.js:100 | 会话在工作区内移动非法 |
| workspace/session-active | commands.js:127 | 归档撞上运行中工作，details.activity 按族列 turn/subagent/job/schedule |
| session/not-found | commands.js:124 | 归档/pin 的目标会话未知 |
| gateway/bad-request | 改名空标题 commands.js:43；createDirectory 坏 payload directory-picker.js:116 | 请求非法 |
| gateway/cancelled | directory-picker.js:171 | 调用方 abort（超时/断连），不是后端故障 |
| gateway/internal | directory-picker.js:157,174 | 非 seam 故障的兜底 |
| directory-picker/unavailable | directory-picker.js:130 | 要的 capability 与装配的不一致，带 {capability} 标明实际装的是啥 |
| directory-picker/unreadable/exists/create-failed | directory-picker.js:143-145 | browse 原语业务失败，均带 subject path |

### 3.5 用户可见的失败形态

- 取消：null，不是错。macOS osascript exit1＋User canceled（native lib/index.js:241）；Linux zenity/kdialog exit1（L246-266）；Windows 对话框取消走 done path-null（L168-199）；browse 对话框 dismiss 即取消（browse README:32）。本仓同：raw===null→resolve(null)，取消类抛错（cancel/dismiss/abort/close 正则）静默收场（dir-picker.ts:61-72）。
- 真故障：Linux 无 zenity/kdialog 即 actionable reject，不回退打字框（native README:36,99）；chooser 启动失败、abort（WM_CLOSE 关窗）→ occupant onError → 文件夹错误对话框，Choose again 重开。
- 并发：directoryBusy 置位期间 shortcut 与二次打开被拒（directoryBusy 文案：正在选择或添加工作区）。
- 无 picker 装配：Add workspace 整项不渲染（ui-workspace/README.md:94）。

### 3.6 本机装配结论

- web profile：directory-picker ＝ dsh-host-directory-picker-auto（boot 时二选一）。本机 Windows＋本地浏览器大概率 native（IFileOpenDialog 子进程，标题固定 Select Workspace Directory）；远端浏览器则 browse。运行时 kind 以 capability().kind 为准，未知 kind 一律藏入口不报错（seam README:52-56）。本仓双路径已覆盖，真机验收时以实际走到的那条为准（未决 U6）。

### 3.7 本仓现状缺口（T6 输入）

- 今天 openDirPicker 返回的只是路径字符串，随后只写 meta.json/调 bot.workspace.set（panel-actions.ts:104-156），从未注册成 DSH 工作区：选了一个 DSH 不认识的目录，左侧栏不会出现它，会话归属也查不到它。这是 T6 必须补的 workspaces.create({path})＋等投影刷新再落家。

## 4. 老数据映射成默认家

### 4.1 四源盘点（只读实测，数量见 §1.5）

| 源 | 位置 | 键形状 | 本机量 |
|---|---|---|---|
| DSH 注册表 | storages/workspace.json | workspaceId→{path,title,sessionIds[]}＋workspaceIds 序＋归档/置顶集＋defaultWorkspaceId | 13 区 |
| 本插件账本 | integrations/dsh-im-companion/meta.json | names[wsPath]、avatars[wsPath]、locals[{name,workspace}]、presets/ctxEnhance/welcomed | names 2，avatars 1，locals 2（均有 ws） |
| dsh-im 绑定 | integrations/dsh-<channel>/workspaces.json | {version, workspaces:{botId: wsPath}, agentPresets, contextEnhancement}（v1/v2，ENOENT→空文档） | feishu v2，7 bot |
| 运行快照 | connection.status 各渠道 bots[{botId,channel,workspace(path串),health}] | path 字符串，未 canon | 随轮询 |

### 4.2 连接键：规范路径（唯一跨三套的公共语言）

- DSH 注册表认 realpath canon（§3.2）；dsh-im 存的是各渠道上报的原始绝对串；本仓 names/avatars 以精确＋归一化（斜杠/大小写/尾杠）双命中（model.ts:83-94）。迁移时必须先规范化再 join：以 create/resolveByPath 回来的 canonical path 为准回写（未决 U8）。
- workspaceId 不可作长期外键唯一依据：删后重加同目录＝全新 id、会话不回来（注册表 README:76-77,171-176）。家行双存 id＋path（§2.4）。

### 4.3 默认家生成规则（确定性、可重跑）

1. 取 DSH items 全集（含无人之区——listHomes 语义，adopt/panel.ts:29-40）：一区一家，home.workspaceId/path/title 照抄，workspaceIds 序即家序。
2. locals 中有 workspace 且命中某区 path→并入该家（空壳退场，binding-commit.ts:60-69 家即其名语义的批量版）；locals 有名无 ws→暂存区（boardGroups 未绑定置顶语义，adopt/model.ts:99-113）。
3. bots 按 workspace path 归属挂到家下（homeList 有人家＋无人之家追尾，adopt/model.ts:92-97）；workspace 为空串的 bot 进暂存区，不丢（unboundBots，adopt/model.ts:33-35）。
4. 归档/置顶集是注册表全局属性，会员位不动（spec.js:46-53；README:116），迁移原样保留，不参与分组。
5. DSH 里已删注册、但 dsh-im/meta 还指着该 path 的→家行标孤儿（path 悬空），重选即按 §3 新建；不得自动 create 复活（复活的是空壳新 id，会话回不来）。
6. defaultWorkspaceId 对应的区若无家→同样生成一家（不特殊命名，命名走 §4.4 回落；DEFAULT_WORKSPACE_DIRECTORY 仅展示层本地化，default-workspace.js:26-28）。

### 4.4 命名回落（与 Q5改名优先对齐：用户显式改名永远赢）

- 链：meta.names[canonicalPath]（精确→basename旧键→归一化，model.ts:95-100）→ DSH title（若恰为 default-workspace 则展示本地化默认名，workspaceDisplayTitle，default-workspace.js:26-28；确认框 seeding 规则见 ui-workspace/README.md:80：untouched 确认即 pin 住当前名）→ 目录基名 → 首个 bot 名。homePlate 门牌口径（大名/副基名/首字/色板）复用 viewName（adopt/model.ts:78-87）。

### 4.5 头像回落

- 链：meta.avatars[canonicalPath]（同三级键，model.ts:101-105）→ 该区首个在线 bot avatarUrl（model.ts:155,211）→ 默认图（T3 定格式）。注意 meta.json 里 avatars 今天是 dataURL（setAvatar 15MB 门限，meta-store.ts:150-155），迁往图存文件、json 只存路径（Q5 既定）是 T3/T6 的事，本票只登记现状不可持续。

### 4.6 删除/重建语义（迁移必须遵守）

- DSH 删注册＝只删分组，会话历史、目录、文件全留；会话变 ungrouped；同目录重加＝新 id 空会话（注册表 README:76-77,171-176）。
- 故迁移是认 path 不认命：家跟 path 走；id 只当本轮展示键。
