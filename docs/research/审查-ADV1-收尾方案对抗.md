## 路线必要性与替代方案（含更短路径评估）

**判定：T9 的「安装态切换」是必要条件，没有等价更短路线。** 证据：自有读取器 `update-reader.ts:164-178` 用 `realpath(profileDir/node_modules/<pkg>)` 逐字照抄上游判据算 `sourceInstall`；`link:` 下 realpath 落到本仓 ⇒ 必 `source-install` ⇒ 既不自装也不给手工命令（`dist/commands.js:44-74`）。想绕过只能伪造 `sourceInstall=false`——那是假绿，且与「真机升级」判据直接冲突。`file:`/tarball 同样不满足 `registrySpec`，故"本地打包 tarball 装"不成立。

**替代 A（更低危，但证据弱一级）**：不动 web，另起临时 profile（`dsh plugin --profile t10 add --save-exact dsh-im-companion@0.1.8` → `dsh --profile t10 …`）验收。代价两条：① 偏离 owner 冻结基线⑩（"web profile 真机"）；② **更关键**：应用内安装有两套路由——`runDesktopService`（`store.js:283-296`，要求 Desktop 注入 `desktopPnpm`/`desktopProfiles` 且 `sameDir` 通过）与 CLI 兜底 `runCliProcess`（`store.js:297+`）。CLI 启动的宿主里前者缺席 ⇒ 验的是**另一条路由**，而用户真实路径是前者。**裁决：不走**；只作为"web 切换失败时保住大部分证据"的降级方案记录。

**替代 B（真能省）**：砍流程税 + 合并观测——wizard 阶段 5/6（tag/Release）与证据无关；"自动检查触发"与"0.1.9 生效"可共用同一次重启的 60s 首查窗口（见覆盖表）。重启次数由 3 压到 2。

## 切 profile 的后果与是否回退（含对用户开发流的影响）

- **后果（已确认）**：`web\node_modules\dsh-im-companion` 由 Junction 变真目录 ⇒ **本仓 `lib/` 改动不再进宿主**；AGENTS.md 的「生效门」（hash 一致 + Ctrl+F5）与用户 2026-09-04 裁定「热更新优先」同时失效；面板此后跑的是**已发布**快照，本仓任何未发布迭代在面板上不可见。
- **附带半径（方案未提）**：同一个 `dsh plugin add` 会跑 `reconcilePlugins`（`plugin-Ddi42qoW.js:46-78`）并**重写 `dsh.profile.bundles`**——此刻任何 `link:` 包（bill/calorie/chef/home/memo/schedule 六个）若解析失败即被**摘出 bundles**，下次启动"少一层"，与那次 self-heal 事故同款。这不是"本插件的事"。
- **对开发流的意义**：Junction 是这个仓的日常开发承重件，不是可有可无的便利；版本号安装只是**验收手段**，不是交付形态。
- **建议：验收证据取满后改回 `link:`（命令 B）**。决定性理由：用户已裁定热更新优先、无必要绝不重启，而回退恰好**不需要立刻重启**——先把磁盘状态修回（用户不断线），宿主半留到用户下一次自然重启生效；若用户想立刻恢复开发流再单独询一次。
- **代价必须让 owner 知情**：改回 link 后，日常面板恒显「当前是从源码安装的」（`reasons.ts:9`），更新中心在日常环境不可用。这是诚实设计、与本次验收不冲突；若 owner 要"日常也可用"，正解是另开 dev profile 挂 link（新增工作，不属收尾）。

## 回滚充分性

**够用**：A/B/C 三条命令覆盖 link↔版本号双向与"改坏了"；"先装好、核验无误，再重启"的顺序警告正确；`sameDir` 不挡、`add` 不被拒已由 T10 前置探明。

**不够（按危害排序）**：① 只备份 `package.json`，**没备份 `pnpm-lock.yaml`**——`pnpm add` 会重写锁文件，"已知好状态"应能逐字回退；② 回滚 C 用 `package.json.bak-before-t9-*` 通配 → 多份备份时 `Copy-Item` 目标二义（可能只拷第一份或报错），应写"取最新一份并校验只有一份"；③ 未点明**回滚不需要重启**（这正是用户裁定在意的性质）；④ 核验只到 `package.json` + `LinkType`，缺"bundles 项数 == 17"与"其它六个 link 仍在"；⑤ EPERM 处置里的"先停 web 宿主"未标出它会**杀掉执行会话**；⑥ 缺**发布侧**回滚口径：包已发不可撤，唯一回退是把 profile 改回 link（本仓即 known-good），要写进手册。

## 建议砍掉/调整的步骤

1. **砍/降级**：wizard 阶段 5（tag）/6（Release）——与目的地证据无关且会断点；验收后补跑（幂等）。若想留第三说明源（GitHub Releases）则照跑，但**不得阻塞验收**。
2. **改**：T10"改间隔后观察一次真实触发" → "重启后 60–90s 观测 `nextCheckAt` 迁移"；档位只验选择态。
3. **合并**：自动检查首查观测 + 0.1.9 生效，共用同一次重启。
4. **加（T9 前置）**：`npm view dist-tags`；CHANGELOG 双源可达性；备份 lock；bundles 项数对账；"装好未重启"检查点；重启前清单落盘。
5. **加（收尾）**：改回 `link:` + 一次可延后的重启 + 面板「源码安装」态截图。
6. **砍**：再加审查轮次（T8 已两轮审查 + 两轮验证）——预算应全给真机。

## 评分与裁决

- **收尾方案达成目的地的可信度：72 / 100**。路线方向正确且必要；扣分在：自动检查验收条款不可执行、重启杀会话未预算、回退步缺失、备份面不全、说明源假阴性未前置。
