## §2 逐条攻击（攻击 → 证据 → 判定 → 处置）

### A1 前提攻击：「上游没有清空语义」是穷举还是抽样？

* 证据：上游包 5.1.0 全包 grep `workspace.(clear|unset|remove|delete|reset|unbind|null)` **零命中**；26 个 `bot.*` 端点穷举，唯一写指针者 `bot.workspace.set`（`plugin-src/host/channels/shared/workspace-rpc.mjs:3,5-15`）；`bot.delete` 连带删指针但连机器人/凭据/账号配置一起删（`token-bot-controller.mjs:266-293`）。
* 判定：**成立，但绑定版本**——取证基于本机实装 **5.1.0**；插件声明兼容下限 4.17.1（`package.json` `dshImCompat.range`）。**未取证**：4.x 老版本是否曾接受空 workspace（若曾，原代码当年是对的，后来上游改了契约）。
* 处置：新代码对老版本**无害**（不发远端就不会被拒）；缺口记入 §4 风险表。

### A2 覆盖面攻击：还有别处会下发空工作区吗？

* 证据：grep 全部 `bindBot(` 调用点——`home-move-ops.ts:86/91/152/157`、`home-ops.ts:236/271`——**全部传真实路径**（`target.path`/`src.path`/`path`/`home.path`）；空串调用点归零。
* 判定：**成立**（修复面完整）。
* 处置：把「不得传空」升级为**守卫**（#158 缺口 1）——注释防不住第二次。

### A3 回归攻击：搬家/重绑还写不写远端？顺序有没有被改坏？

* 证据：`home-move-ops.ts:84-94` 搬家＝先 `bindBot(target.path)` → 后 `assistant.move`，失败回滚 `src.path`；`:143-163` 重绑＝先 `bindBot(path)` → 后 `home.rebind`，失败回滚 `home.path`。两条链的「远端先跟随」**原样保留**。
* 判定：**成立，无回归**；verify `T10b #127` 仍钉着顺序与回滚。

### A4 可判定性攻击：验收时只看磁盘日志，能判定「已修好」吗？

* 证据：`src/log-events.ts:92-93`——`home.action` / `assistant.action` 均 `level:'info'`、`kind:'resident'`（debug 开关关着也落盘）；客户端 `aLog`（`home-ops.ts:16-17`）打的正是 `assistant.action`；宿主 `describeCall` 有 `assistant.unbind`（`log-sites.ts:64-65`）、`assistant.remove`（`:60-61`）。
* 判定：**成立**，判据见 §5。

### A5 可判定性攻击（反向）：**删家**的语义行缺不缺？

* 证据：`src/host/log-sites.ts` 的 `describeCall` **没有 `home.remove` case** ⇒ 删家只剩 `host.rpc.call` 的 debug 明细（debug 关着就不落盘）⇒ 违反本仓「事后只看磁盘日志就能判定」的纪律。
* 判定：**缺口成立**（不影响修复正确性，影响可判定性）。
* 处置：**#158 缺口 2**。

### A6 状态机攻击：解绑后那个机器人真能被别的助理捡走吗？

* 证据：`isBotBound` 只认 `status==='bound'`（`home-model.ts:131-135`，注释逐字「unbound 占位不占号，后续可认领」）⇒ 解绑后不占号；`freeBots`（`:195-201`）把它放回空闲池；绑定弹层候选＝`freeBots`（`home-bind-forms.ts:41-48`）；再绑时 `bindBot(channel, botId, home.path)`（`home-ops.ts:271`）用**新家路径**覆盖旧指针 ⇒ 自愈。模型层两半都有 verify（`home-steel.ts:244-245`、`:282`）。
