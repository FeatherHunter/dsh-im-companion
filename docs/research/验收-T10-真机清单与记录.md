## 一、起点（已核，2026-09-12）

- 活跃 profile = **web**（`profile-selection/state.json`）；本地安装 = `dsh-im-companion@0.1.8`**真目录**（非 link），`dsh.profile.bundles` 18 项。
- 官方源 `latest = 0.1.9`；公开 tarball 的 host 半是 `fetch.register` 版、client 半带 `0.1.5-rc.2` 兼容标记。
- 两份版本说明源**都已含 `## v0.1.9`**（jsDelivr 缓存已 purge，否则对话框会假阴性）。
- 宿主日志已证：调度器按「**启动后 60 秒首查**」装配，作用域 = `…\.dsh\profiles\web`。

## 二、五态清单（请把看到的原文记下来）

1. **检查更新** → 面板应显示「发现新版 **0.1.9**」。
   - 若刷新后顶部胶囊显示 0.1.9、而更新中心显示「当前 0.1.8」：**以更新中心为准**——本仓刚重建到 0.1.9，宿主此刻仍在跑安装版的 0.1.8，属正常。
2. **自动检查** → 默认开、24h 一次，宿主启动后 60 秒做首查。
   - 看「下次检查」：若已是「约 24 小时后」= 首查已跑过且成功。
   - 面板**不应**出现「自动检查不可用」。
3. **点「安装」** → 走应用内路由（`runDesktopService`）→ 期望「已装好、待重启」。
   - 失败也**算有效验收**：面板应给失败原因 + 一条可复制的手工命令，请把灰字原文记下。
   - 已知风险：宿主在跑时 pnpm 覆盖安装目录可能 `ERR_PNPM_EPERM`（T9 实测过同形问题）。手工兜底 = `dsh plugin --profile web add --save-exact dsh-im-companion@0.1.9 --registry=https://registry.npmjs.org`；若它也 EPERM，先删 `node_modules\dsh-im-companion` 再装。
4. **待重启 ⚠️ 横幅** → 文案须含「新版 0.1.9 已装好、重启后生效」，并说明这不是失败；该状态下不应再显示安装按钮（手工命令入口保留）。
5. **版本说明对话框** → 应显示 CHANGELOG 的 **v0.1.9 那一节**。
   - 若显示「暂时取不到更新说明」：**先判环境再判缺陷**——raw 直连在本机不稳（T3 实测无代理 6 次成 1 次），重试一次通常即可。
