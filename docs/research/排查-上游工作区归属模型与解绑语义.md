## 结论速览

1. **「机器人 → 工作区」指针全仓只有一份，存在两张表里**：磁盘态是 `<DSH_HOME>/integrations/dsh-<channel>/workspaces.json` 的 `workspaces[botId] = "<绝对路径>"`（落盘校验强制非空绝对路径，`src/channels/shared/bot-workspace-store.mjs:250-256`），内存态是 `#workspaces[botId]`（同文件 `:410`）。另有第三张「会话级覆盖」表 `#conversationWorkspaces[botId][conversationKey]`（`:418`）。**对外状态里的 `workspace` 字段恒为非空**（`:1316`）⇒ 上游从来没有、也不可能对外表达「这个机器人没有工作区」。
2. **指针的写者只有 4 处**（全部已读原文）：端点 `bot.workspace.set`（`:770-804`）、启动期 `ensure()`（`:705-768`，只给**新** bot 写）、启动期 `reconcile()`（`:1289-1306`，删孤儿）、`bot.delete` 之后的 `retireAfterConfigCommit()`（`:1267-1273` → `:1367`）。**没有第二个端点能写它**。
3. **「机器人没有指针」是合法但不稳定的状态**：内存态允许缺失（`has()` 为假，`:479-482`），但下一次渠道启动 `ensure()` 会给它补一条**指向默认工作区**的指针（`:713` + `:735-740`），而 `reconcile()` 会把「不在账号配置里」的 bot 的指针删掉（`:1303-1305`）⇒ 「无指针」只在两次启动之间存在。
4. **没有任何端点或宿主调用能产生「机器人还在、但工作区指针被清空/释放」的状态**（§3 全表）。能产生「指针缺失」的只有两条内部路径：落盘失败回滚（`:751-759`）与 `bot.delete` 后的 retire（`:1367`）；两者都不是稳定状态。**上游只有「设定归属」，没有「清空」语义——已用源码确证。**
5. **官方 UI 根本没有「解绑工作区」这个动作**：机器人卡片里的工作区编辑器只有「选择目录」一个按钮（`plugin-src/client/workspace-editor.js:52`），且 `pick()` 在没选中目录时直接 return（`:23-28`）⇒ **物理上提交不了空值**；卡片底部只有「检查连接 / 重试连接」与「移除接入」（`plugin-src/client/channels/weixin/index.js:285-287`），而「移除接入」= `bot.delete`（把机器人、凭据、账号配置全删）。
6. **默认工作区 = `<DSH_HOME>/im`**（`src/channels/shared/default-workspace.mjs:5-8`），本机 `DSH_HOME=C:\Users\辰辰洋洋\.dsh` ⇒ **`C:\Users\辰辰洋洋\.dsh\im`**。上游眼里「默认/未分组目录」与「某个具体家目录」的差别是**会话怎么建**：未分组目录用 `cwd` 建会话、归「未分组」、**不注册成 DSH 工作区**；具体目录会先被 `workspace.create` **注册成 DSH 工作区**再按 workspaceId 分组（`src/channels/shared/harness-client.mjs:1334-1351`）。本机注册表 `~/.dsh/storages/workspace.json` 实证：两个具体目录在册、`~/.dsh/im` 不在册。
7. **改绑只覆盖指针 + 清该机器人的会话映射**（`:794-795`）；agentPreset / model / alias / busyMessageMode / contextEnhancement / deliveryTargets / accessPolicies / conversationWorkspaces 这些残留**全部以 botId 为键、跟机器人走，不跟目录走**（表定义 `:411-418`，落盘字段 `:1414-1425`）。会话级覆盖在 RPC 改绑路径**不清**（`:770-804` 全程不碰它）⇒ 被钉在旧目录的会话覆盖会继续生效。旧目录内容不会被删/归档（README:273 原文）。
8. **`bot.delete` 删的东西很彻底**：凭据、账号配置、运行时、**该 botId 的 9 张表**（含工作区指针）、会话状态文件（`src/channels/shared/token-bot-controller.mjs:266-293` + `bot-workspace-store.mjs:1367-1375`）。删完**可以**重绑，但**不会**回到旧工作区：微信 botId 由账号确定性派生（`src/channels/weixin/config-store.mjs:25-33`），同一账号重新接入拿到同一个 botId ⇒ 下次启动 `ensure()` 补一条**指向默认工作区**的指针。
9. **本机实况**：`wx_d3c34f555e4f2542fd2db9c7` 处于**形态 1（显式指针）**——指针 `D:/dsh-plugin/dsh-opencode-palette`（目录存在、与插件的家表一致），另带 1 条 allowlist 型访问策略，无 agentPresets/models/aliases/conversationWorkspaces 段。
10. **推荐修法：候选 (a)「只解绑本地、远端指针原样留着」**——删掉客户端三处 `bot.workspace.set(workspace: '')` 前置（`src/client/components/home-move-ops.ts:110` / `:128` / `:172`）。它是**唯一不引入任何远端调用**的语义 ⇒ 解绑链不再有可失败点，#156 这一类「必现失败」被根除；旧指针是**可自愈**的（下次搬家/重绑的既有「顺序铁律」路径会覆盖它）。(b)/(c) 都要再塞一次远端写，而远端写必然带来「会话映射被清」这一用户可见副作用（README:273 原文）。

#### 1.3 机器人指针一共几种形态？—— 4 种

1. **磁盘态**：`workspaces.json` → `workspaces[botId] = "<绝对路径>"`（非空；落盘校验强制）。
2. **内存态**：`#workspaces[botId]`（绝对路径字符串；**可以缺失**）。
3. **会话级覆盖态**：`#conversationWorkspaces[botId][conversationKey] = "<绝对路径>"`；`null` 的语义是「清掉这条覆盖、回落机器人工作区」（`:1020`、`:1038-1041`），**不是**清空机器人指针。
4. **对外呈现态**：状态里的 `workspace` 字段（`:1316`）—— 永远非空 ⇒ **外部无法区分「显式指向默认目录」与「无指针」**。

### 2. 状态空间

**上游允许「机器人没有工作区指针」吗？允许，但它不是稳定状态。**

- 允许：内存态可缺失（`has()` 返回假，`:479-482`）；磁盘文件里没有该 botId 就是没有。`:751-759` 的落盘失败回滚就会制造这种状态（bot 留在账号配置里却没有指针）。
- 不稳定：下次渠道启动时 `ensure()` 会给它补一条指向**默认工作区**的指针（`:713` `createsBot=true` → `:735-740`），而 `reconcile()` 会把「不在账号配置里」的 bot 的指针删掉（`:1303-1305`）⇒ 「无指针」只在两次启动之间存在。

**没有指针时回落成什么？**

- 路径：`#defaultWorkspace` = `resolve(config.workspace ?? ungroupedWorkspace)`（`src/channels/shared/default-workspace.mjs:21-25`）⇒ 本机 = `C:\Users\辰辰洋洋\.dsh\im`。
- 目录是否自动创建：**只有当路径等于「未分组目录」时才自动 mkdir**（`default-workspace.mjs:27-31`，由 `ensure()` `:726-728` 调用）⇒ 其它目录不会因为启动插件而被创建（README:171 同义原文，见 §8）。

**指针指向已不存在的目录时会怎样？**

- **落盘期不报错**：`normalizeDocument` 只校验形态（`:250-256`），不校验存在性。
- **启动期不报错、也不自愈**：`ensure()` 对已有指针只做「同未分组目录才 mkdir」（`:722-728`），不校验存在性；`reconcile()` 也不校验 ⇒ **悬空指针静默存活**。
- **真正用到该目录建会话时**才可能在 DSH 宿主侧失败（`cwd` 不存在 / `workspace.create` 指向已删目录）。该失败的确切错误与是否自愈**来自 DSH 宿主，本轮未读到宿主源码**（`D:\DeepseekHarness\resources\app.asar\dsh\` 为 asar 打包、未解包）⇒ **未确证**，见末节。

### 6. 改绑残留（同一 botId 改绑到另一个目录）

- **旧指针是否被完全覆盖？** 是。`:795` 单键赋值 `this.#workspaces[id] = workspace`，旧值只在 `:787` 暂存、用于 `:799` 的落盘失败回滚 ⇒ 成功路径上磁盘只剩新值。
- **同时发生什么**：`:790` 换代（generation）→ `:794` `await clearSessions?.()` ⇒ **该机器人的「聊天 ↔ 会话」映射被清空**（微信渠道：`src/channels/weixin/state-store.mjs:183-184` `async clearSessions() { this.#state.sessions = {}; }`；会话状态文件在 `accounts/<botId>/state.json`，路径由 `plugin-src/host/channels/weixin/production.mjs:118` 决定）。
- **不被改绑影响的残留**（全部以 **botId** 为键 ⇒ **跟机器人走，不跟目录走**）：内存表定义 `:411-418`（`#agentPresets`、`#models`、`#aliases`、`#busyMessageModes`、`#contextEnhancement`、`#deliveryTargets`、`#accessPolicies`、`#conversationWorkspaces`），落盘字段 `:1414-1425`。⇒ 换目录后，旧目录的**模型选择 / Agent Preset / 别名 / 访问策略 / 忙碌消息模式 / 上下文增强 / 投递目标**全部**留在机器人身上**。本机实证：该 bot 的 `accessPolicies` 里有一条 allowlist 型策略，改绑不会动它。
- **会话级覆盖 `conversationWorkspaces`**：`setWorkspace` 全程不碰它（`:770-804`）⇒ **被钉在旧目录的会话覆盖会继续生效**；只有 `/session` 绑定路径会清（`:1171-1176`）。
- **目录级残留**：旧目录里的**内容**不会被删 / 清空 / 归档（README:273 原文：「切换只清除该机器人的旧聊天映射，不会删除、清空或归档旧 Session」）；DSH 侧工作区注册表里那条旧目录的记录**跟目录走**，上游改绑或删机器人都**不会**注销它（上游只有 `workspace.create`，源码里没有 workspace 删除调用）⇒ 旧目录会长期留在 DSH 的工作区列表里。
- **摘要**：改绑 = 「指针换成新目录 + 清会话映射」；其余一切按 botId 键的状态**跟着机器人走**，按目录键的状态（DSH 工作区注册条目、目录里的文件与会话）**跟着目录走**。

## 对 #156 决策的含义

### 三个候选的共同前提（源码确证）

1. 上游**没有**「清空」语义（§3）⇒ 任何修法都不可能让远端指针变空；可做的只有「写一个新值」或「不动它」。
2. 「写一个新值」必然带副作用：**改指针 + 清该机器人的会话映射**（`:794-795`）⇒ 机器人会丢聊天↔会话绑定（README:273 明文）。这是**用户可见**的行为变化。
3. 本仓规格里「移除渠道」= 解绑、不断连（见关联笔记），而当初清远端的理由（防种子复活）已被 #141 在种子层核销。
4. 改绑的其它残留全部跟机器人走（模型 / 预设 / 别名 / 访问策略…，§6），不会跟目录走 ⇒ **换目录不会「带走」或「洗掉」机器人的其它设置**。

### (a) 只解绑本地、远端指针原样留着

- **会发生什么**：客户端去掉 `bindBot(..., '')` 那一步，直接落本地解绑（`assistant.unbind`）。上游指针保持 `D:/dsh-plugin/dsh-opencode-palette`；机器人连接不动（本来就是规格承诺）。
- **残留什么**：远端指针停在旧目录；旧目录仍是 DSH 注册工作区（`~/.dsh/storages/workspace.json` 里那条记录跟目录走，不会被清）；该 bot 的模型 / 预设 / 别名 / 访问策略 / 会话级覆盖全保留（跟机器人走）；旧目录内容与会话文件一律不动。
- **风险**：① **幽灵占用**——机器人仍在线、仍按旧目录工作，而插件侧显示「未绑」；若用户随后删掉那个家，远端指针会悬空（上游不报错也不自愈，§2）；② 插件的种子对账不会因此补出助理行（#141 已修，见关联笔记）⇒ 不会「复活」；③ 悬空指针**可自愈**：之后再把该机器人绑给别的助理/家时，现有的「顺序铁律」路径（`moveAssistant` → `bindBot(..., 新路径)`、`rebindHome` → `bindBot(..., path)`）会覆盖它。
- **确定性**：**全源码确证**。它是三个候选里**唯一不引入任何远端调用**的 ⇒ 解绑链不再有可失败点，#156 这一类「必现失败」被根除。

### (b) 改绑上游默认工作区 `C:\Users\辰辰洋洋\.dsh\im`

- **会发生什么**：解绑前先 `bot.workspace.set(workspace = <DSH_HOME>/im)`；上游把指针改成默认目录（行为上等价于「没有显式绑定」，但落盘上仍是一条**显式**指针）。副作用：**该机器人的会话映射被清**（`:794`）⇒ 正在进行的聊天失去会话绑定；之后的会话走 `cwd`、归「未分组」（`harness-client.mjs:1346-1350`）。
- **残留什么**：同 (a) 的按-botId 表残留 + 「聊天↔会话绑定被清」这一新增残留；旧目录内容不动。
- **风险**：① 又在解绑链里塞了一次**可能失败**的远端写（目录不存在 / bot 不存在 ⇒ 要么再次 fail-closed 复现 #156，要么 best-effort 后指针仍停在旧值 ⇒ 退化成 (a)）；② 会话绑定被清是用户可见的行为变化（正在聊的会话断链）；③ 若用户给 dsh-weixin 显式配过 `workspace`（`default-workspace.mjs:23` 的 `config.workspace` 优先），「上游默认」就不是 `~/.dsh/im` ⇒ 硬编码会写错目录（本机未发现这样的配置，但渠道插件配置的存放位置未穷举 ⇒ 推断）。
- **确定性**：写指针 / 清会话 / 未分组机制**源码确证**；「用户可能改过 `config.workspace`」是**推断**。

### (c) 改绑插件登记的「默认工作区」家 `D:\Users\辰辰洋洋\Documents\deepseek-harness\default-workspace`

- **会发生什么**：解绑前 `bot.workspace.set(workspace = 该家路径)`。该目录在 DSH 里**已注册**为工作区（id `e239d325-…`，§5/§9）⇒ 上游 `workspaceId()` 直接复用（`harness-client.mjs:1337-1338`），不会新注册；会话按该 DSH 工作区分组。
- **残留什么**：同 (a) + (b)（会话映射被清）；且该家从此被这个机器人使用 ⇒ 若之后另一个助理也绑到同一个家，**两个机器人共用同一个 DSH 工作区目录**（上游允许——各机器人「工作区独立」是指各自保存指针，不是不能指向同一目录）。
- **风险**：① 目标目录必须存在（`validateWorkspacePath` `:389-396`）⇒ 换机 / 家被删时会失败；② 把上游机器人的默认工作区与插件的「默认工作区」家**语义耦合**——两者本不是一回事（上游默认 = 共享 IM 目录 `~/.dsh/im`；插件默认家 = 插件自建目录），耦合后两边任一处改名/删除都会互相影响；③ 该家被删时远端指针悬空。
- **确定性**：注册 / 分组机制**源码确证**；「插件默认家被删 ⇒ 耦合风险」是**推断**。

### 推荐

**推荐 (a)：只解绑本地、远端指针原样留着** —— 具体改法是删掉客户端三处「先把远端 workspace 置空」的前置：`src/client/components/home-move-ops.ts:110`（`unbindAssistant`）、`:128`（`removeAssistant`）、`:172`（`removeHome`），让「移除渠道 / 删除助理 / 删除家」三链直接落本地。

理由（逐条对应证据）：

1. **契约层**：上游没有清空语义（§3）⇒ 现在这一步**在任何契约下都不可能成功**；留着它就是继续 fail-closed。
2. **规格层**：本仓自己的规格把「移除渠道」定义为「解绑、不断连」，清远端的理由（防种子复活）已被 #141 核销（关联笔记）⇒ 这一步既无必要也无依据。
3. **可靠性层**：(a) 是唯一**不引入远端调用**的语义 ⇒ 解绑链没有可失败点，#156 这一类必现失败被**根除**（而不是把失败从「必现」改成「偶发」）。(b)/(c) 都要再写一次远端，而远端写的失败处理又回到同一个死循环。
4. **可自愈层**：(a) 留下的旧指针会被下一次搬家 / 重绑的既有路径覆盖（`home-move-ops.ts:80`、`:150`）⇒ 它是**临时**状态，不是脏数据。
5. **代价可控层**：机器人仍按旧目录工作、连接不断——这本来就是 UI 文案承诺的（「移除后机器人连接不会断；它可以再绑给别的助理。」，见关联笔记）。

**如果产品确实想要「解绑后机器人回默认目录待命」**，那应当是一个**独立动作**（例如「移回默认工作区」），而不是偷渡进「移除渠道」；那时选 **(b)**，并**显式接受**「会话映射被清、正在进行的聊天断链」这一用户可见代价（README:273 原文），同时必须让该远端写**失败不阻塞解绑**（best-effort），否则又会把 #156 修成另一个必现失败点。
