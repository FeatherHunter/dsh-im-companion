## 真机验收前必须补的点

1. **P0 整改后复验**：断桥/宿主未就绪（mock 或杀载体）时面板文案，必须不再出现「已是最新版本」。
2. 设置段关闭→重开、切段往返、插件热重载三路都走一遍：不得出现永久「安装中」（P1-c 只在桩上验过）。
3. 热重载/顺序倒置窗口：新实例挂载时面板已存在 ⇒ 面板必须立刻有内容（P0-b 认领路径只能真机验）。
4. `pending-restart` 态：横幅常驻、无安装按钮、关掉说明窗后横幅仍在、命令入口可用（整改后）。
5. 版本说明三态实机：正常联网、断网、无该版节；断网时不得出现「你没有网络」类文案。
6. 关开关即时性：面板「下次检查」应立刻变「—」，且宿主自动检查不再触发（可查宿主日志/nextCheckAt=null）。

- **裁决：需整改**（可在整改后进 T9/T10）。

整改项（按严重度）：

1. **P0｜桥级失败谎报「已是最新」**：`res.ok===false && token===null`（rpc 抛错/超时、`rpc===null` 无载体、无回包）时 `deriveState` 落 `latest`（data.ts:23-32 + phone.ts:105-107），且 `res.message` 从不展示 ⇒ 面板显示「已是最新版本（未知版本）」。需为无 token 的失败单独渲染（复用灰字槽 + 展示 message），不得落 latest。
2. **P1｜待重启态缺 §9 手工命令入口**：view.ts:150-158 命令块只在 `blocked` 分支，违反 §C.1 / §B `pending-restart` 行 / README §10.3。
3. **P1｜手动检查失败无 toast**：§D.4 要求瞬时 toast；共享件 `src/client/ui/toast.ts:7` 现成可用，feature 内零引用。
4. **P2｜文案漂移**：reasons.ts:13 `registry-conflict` 多出「，或用下面的命令覆盖安装。」（该 token 在包内不可达，但 §B 要求逐条一致）。
5. **P2｜`-rc.N` 预发版本切节失配**：changelog.ts:13-17 把标题尾缀抹掉后只比三段号，导致预发目标永不命中、稳定目标可能命中 rc 节（§E.3/取证 §2.4#6）。
6. **P2｜meta 读失败后写入覆盖宿主档位**：data.ts:141-155 读失败即保持默认 24 且不重试，用户之后任何一次开关/档位写入都会把宿主里的 168 覆盖成 24（建议读失败后重试或写前以宿主值回填）。
7. **P3｜在途态缺失**：§3.2「请求在途 → 按钮变『检查中…』并禁用」未实现（连点两次会发两通 check；宿主静默合流，实害小）。
8. **证据类**：把 view.ts（DOM 桩范式照 left-filter/first-view）、`setPrefs`/`loadPrefs`、`text.INTERVALS`、`fetchNotes` 两源回退与超时补进 verify 第 19 段；文案断言改为与档案 §B 的单一真相源比对，避免第二份副本漂移。
