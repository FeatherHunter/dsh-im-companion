## §0 五处修正（按严重度）

1. **「现网调用点已归零」不成立（严重）** — 初版据工作树 grep 断言全部 `bindBot` 调用点已传真实路径。`git diff HEAD -- src/client/components/home-move-ops.ts` 证明 **master `cd4b372` 仍有三处空串硬前置**：
   - `unbindAssistant`：`const src = deps.getHome(a.homeId); if (!await bindBot(rpc, a.channel, a.botId, '')) return`（失败回滚 `bindBot(src.path)`）；
   - `removeAssistant`：`if (a.status === 'bound' && a.botId) { if (!await bindBot(rpc, a.channel, a.botId, '')) return }`；
   - `removeHome`：`for (const a of bound) { if (!await bindBot(rpc, a.channel, a.botId, '')) throw new Error('远端工作区没清掉，已中止：家的记录一行没写') }`（失败回滚 `home.path`）。
   这些在工作树已被 #156 修复（`fix/156-unbind-remote` 已推、未合并），但 **master 与在跑的真安装 0.2.19 都不含修复**（#156 C4/C5：修法已落码、未发布）。⇒ 本票守卫必须与 #156 修复**同批上线**，不能单独先发。
2. **守卫静默失败（新风险）** — master 的 `bindBot` 失败路径本来就会 `toast('绑定失败：' + String(raw?.error?.message ?? '绑定失败'))` + `aLog('bind-bot','',false,...)` + `return false`；票面初版守卫只 `aLog + return false`，而调用方是 `if (!await bindBot(...)) return` ⇒ 用户看到「点了没反应」——与 #156 的症状同形。⇒ **Q5：守卫命中必须 fail-loud**。
3. **缺口 2 前提夸大** — 初版「删家成功与否在磁盘上只剩 `host.rpc.call` debug」不对：客户端 `aLog('remove-home', ...)`（工作树 `home-move-ops.ts:177/:179`，resident）在 master 与工作树**都已存在**（`git diff` 上下文可证；#156 C5 明说沿用 `assistant.action`）。真正缺的是**宿主侧** `home.remove` 语义行（`log-sites.ts` 无 case、`log-events.ts` 无声明）。
4. **缺口 2 范围不完整** — `home.rebind` 同样缺宿主语义行：`src/host/rpc.ts:199` 成功回 `{home:r.row}`（与 `:207` 的 home.remove 同形），但 `log-sites.ts` 无 case、`log-events.ts` 无声明；客户端 `aLog('rebind-home', ...)`（工作树 `:158/:161`）同类。票面只列 `home.remove`。⇒ **Q6**。
5. **发版窗口措辞** — #156 Q3 已裁定「保持真安装」⇒ 真机验收＝发布 → `dsh plugin --profile desktop add --save-exact dsh-im-companion@<新版本>` → **重启 DSH**（真安装装配路径变了，热重载吃不下）→ Ctrl+F5；窗口与 **#154 同批**（`审阅-移除渠道修复` §0.4；#156 C4/C5 同口径），不是「仅 #156」。⇒ **Q4 改写**。

附带（不单列问题）：客户端 home 级动作的日志字段错位——`remove-home`/`rebind-home` 走 `assistant.action`（`log-events.ts:93`，字段 `assistantId`），语义上应走 `home.action`（`:92`，`homeId`；`home-ops.ts:14` 已有 `hLog`）。宿主行已够判定，故不阻塞本票，见 Q6(c)。

## §2 修正后的完成定义（建议直接进 agent brief）

**缺口 1**
- 落点：`bindBot` 入口（`home-ops.ts:105-131`）或独立模块（Q3）；谓词按 Q1 裁定（`trim()` 后双平台保守正则 `^(?:[A-Za-z]:[\\/]|[\\/])`）。
- 非法（非 string / 空 / 纯空白 / 相对路径 / `C:` / `~` 等）⇒ **toast**（Q5）+ `aLog('bind-bot','',false,<target> + ': 工作区路径为空/非绝对路径，拒绝下发；收到 ' + JSON.stringify(workspace))` + `return false`；在 5 次重试循环**之前**返回，**零 RPC**。
- 不变量：任何合法绝对路径行为与现在完全一致（含 `workspace-bot-not-found` 重试与 toast）。
- 验收：新增 verify 传空串/`C:`/`agents/x` ⇒ 零 RPC + 日志含 offending 原文 + 返回 false；`npm run check` 全绿；`home-ops.ts` ≤300 行。
- 注：日志断言需在 home-steel 新增 `initLog(fake host rpc)` 接线（先例 log-trace-bridge）；若成本高于预期，至少要用纯函数单测钉住谓词与消息，并在 brief 里说明剩余的手动核对。

**缺口 2**
- 宿主 `log-sites.ts` 补 `case 'home.remove'`（Q6(b) 若同意再补 `home.rebind`）⇒ `{ level, event, fields: { homeId: id, ok: okFlag, message } }`（home.rebind 可加 `workspaceId`/`changed`）。
- `src/log-events.ts` 同步声明 resident（含 traceId）；`tools/verify/log-pipeline.ts` 的 domainCases 补项，断言成功/失败、message 原文、字段子集、resident 落盘（debug 关着也写）。
- 验收：`npm run check` 全绿；真机删家后磁盘出现 `home.remove ok=true`（与 #156 验收同窗口）。
- 不做：不改 #156 已定行为（三链不写远端）；不扩到其它直调点业务代码；不动上游；不新增轮询/通道。
