## 更新包真身的服务访问清单（dist 全量枚举，别漏）

`dist/**` 里对 ctx 的触碰**只有** `host.js` 这几处（其余文件零 ctx）：

| 位置 | 写法 | 分类 | 我方 inject 够吗 | 触发条件（用户操作） |
|---|---|---|---|---|
| `host.js:26` | `const get = ctx?.get` | accessor（`reflect`，根自带） | 够 | 任何一通 update 电话 |
| `host.js:33` | `ctxService(ctx,'desktopProfiles')` | 服务查询（不抛） | 够 | 建能力时（`apply` 期）即执行 |
| `host.js:39` | `const inject = ctx?.inject` | accessor（`registry`，根自带） | 够 | 仅当判定为 desktop |
| `host.js:41-43` | `inject.call(ctx,['desktopPnpm'],cb)` → `desktopCtx?.desktopPnpm` | 嵌套 fiber 内**已声明**该服务 | 够（子 fiber 自带 inject） | 仅 desktop |
| `host.js:100` | `ctxService(overrides.ctx,'subprocess')` | 服务查询（惰性 thunk） | 够 | **仅 cli 路由**，且点"更新/安装"时 |
| `host.js:102` | `ctxService(overrides.ctx,'desktopProfiles')` | 服务查询 | 够 | **仅 desktop 路由**的安装 |

- 包内**没有任何** `ctx.<service>` 形式的裸属性读取——全部经由 `ctx.get()`（免注入）或包自己的 `ctx.inject()` 子 fiber。
- 结论：**包不要求我方 `inject` 增加任何项**；它要的是"宿主有没有那个服务"。

## 尤其：一键安装路径的服务依赖（T10 风险点，最细）

链路：`imc.updateInstall` → `runInstall` → `reader.install()` → `createUpdateExecutor.runInstall` → `installRecipe()`（`commands.js:37-55`）按 `environmentKind` 二选一：

1. **路由判定**：`environmentKind = detectEnvironmentKind(ctx)` = `ctx.get('desktopProfiles')===undefined ? 'cli' : 'desktop'`（`host.js:32-35`）。
   asar 内 `dsh-market` 的原文注释（本机装机产物）：*"Desktop's supported cross-environment contract guarantees that **desktopProfiles exists before Loader entries mount**, and prescribes this presence check plus a nested desktopPnpm injection"* + 链接 `dsh-plugin-desktop/docs/plugin-services.md#L190-L243`。⇒ **在 DSH Desktop 上必为 `desktop`**，走 `desktop-service` 路由（不会走 `subprocess`）。
2. **desktop 路由要 `desktopPnpm`**（`store.js:283-296`）：`service.runPlugin(args, profileDir, undefined)`，且 `sameDir(active.dir, profileDir)` 守卫。
   asar 内桌面服务真身已定位：`runPlugin(argv, invokingDir, signal)` / `runExternalMarketPluginInstall(...)` / `startPlugin()` 里 `assertAbsolutePath('plugin invoking directory', invokingDir)`，实际执行为 `[appExecutable,'--expose-internals',dshBootstrapPath,'plugin','--profile',bootstrap.activeProfileName, ...argv]`，`cwd: invokingDir`。⇒ **方法存在、签名兼容、profileDir 只需绝对路径**（我方 `resolveProfileDir` 返回 `<DSH_HOME>\profiles\web`，绝对 ✓）。
3. **不需要为它加 inject**：`desktopPnpm` 由包的嵌套 `ctx.inject(['desktopPnpm'],cb)` 拿到；`subprocess`（cli 路由）由 `ctx.get('subprocess')` 拿（provider = `@deepseek-ai/dsh-subprocess-local`，本机 profile 已装）。**若真的加进我方 `inject`，反而会让插件在无该服务的宿主上永不装载**（cordis 以必需服务门控 `apply`）。
4. **真正的两个风险（都不是 inject）**：
   - ① `sameDir(desktopProfiles.current.dir, 我方 profileDir)`：桌面服务**忽略调用方传的 profile**，用的是 `bootstrap.activeProfileName`；若 Desktop 当前激活范围 ≠ `web`（我方 profileDir 由 Junction 认出的是 `web`），`runDesktopService` 立刻 `throw fail('install-failed')`。**这是 T10 点"安装"最可能的失败点。**
   - ② `add` 策略：asar 内 market 适配器注释称 *"their Desktop rejects `add` on `runPlugin` outright"*，故 market 对 `add` feature-detect `runExternalMarketPluginInstall`（本机 Desktop **确实发布**该方法）。而 `dsh-plugin-update@0.1.1` 只走 `runPlugin(['add',…])`，**无 boundary 回退**。本机 `validatedArgv` 未见拒绝 `add` 的分支 ⇒ **未决**，T10 必须真机验证。
5. **附带发现（影响 T10 是否在场）**：`profiles\desktop\node_modules\dsh-im-companion` 是**真目录 0.1.2**（`inject=['connection']`，且**根本没有** `lib/host/update.js`），而 `profiles\web\...\dsh-im-companion` 是 Junction → 本仓 0.1.7（hash 与本仓 `lib/index.js` 一致）。两侧**不是同一份代码**；若 Desktop 激活 desktop 范围，跑的是无更新系统的 0.1.2，T10 的功能压根不在场。

## 判据：怎样确认某属性是 mixin accessor（可复用）

1. 读 `@deepseek-ai/cordis/lib/index.js:671-698`（proxy `get` trap）：`Reflect.has(target,prop)` 命中才走普通属性；否则看 `target.reflect.props[prop].type`——**`'accessor'` 就走 `def.get.call(ctx,…)`**，其余走服务解析瀑布，失败即 `cannot get property "X" without inject`（`:675`）；`prop in fiber.inject` 时文案换成 `cannot get required service "X" in inactive context`（`:687`）。
2. 找"谁注册的 accessor"：`rg -n "mixin\(" <pkg>/lib/index.js`。已知命中：
   - `cordis-plugin-timer/lib/index.js:7`（源 `src/index.ts:15`）：`ctx.mixin('timer',['timeout','interval','throttle','debounce','setTimeout','setInterval'])` ⇒ **accessor，source 服务 `timer` 是"别的 fiber 提供的服务" ⇒ 必须注入**。
   - `cordis/lib/index.js:735-752`：`reflect`/`fiber`/`registry`/`events` 四组 —— 也是 accessor，但 source 是**根 ctx 自带**，故 `ctx.effect`/`ctx.inject`/`ctx.provide`/`ctx.get` 免注入可用。
3. 一句话判据：**`ctx.get(name)` 免注入、取不到返回 `undefined`；`ctx.name` 必须注入、未注入在取值那一刻就抛**（`cordis:755-771`）。

## inject 最终建议

```ts
export const inject = ['connection', 'timer']   // 维持现状，不加项
```

- `connection`：`src/index.ts:40` 的 `/api/im-companion` 载体（`connection.fetch.register`），不注入即装配期抛。
- `timer`：`src/host/update.ts:105-106` 的 `ctx.interval`/`ctx.timeout`（accessor，source 服务在别的 fiber）——**2026-09-12 冷启动事故的那一项**；`ctx?.interval` 拦不住，降级分支永远到不了。
- **不要**加 `desktopProfiles` / `desktopPnpm` / `subprocess`：包用 `ctx.get()` + 嵌套 `ctx.inject()` 取它们（免注入）；加成必需注入会让插件在 web/无桌面宿主上**永不装载**（cordis 以必需服务门控 `apply`），是比漏注入更重的故障。
- 若不改（现状）：**没有任何已知路径会抛 "cannot get property … without inject"**；T10 的失败若发生，会是 `install-failed`（第 4 节 ①②），不是本类事故。

## T10 真机验收风险

**中**。注入维度 **低**（清单闭合，无遗漏）；安装路径 **中**——先验"Desktop 激活范围是否 = web"（决定 ①），再验点"安装"是否被 `runPlugin(['add',…])` 拒绝（决定 ②）；两者任一命中即 `install-failed`（**不会**重现冷启动那种整树装配失败）。
