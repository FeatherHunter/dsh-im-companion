## 真机风险判定（②③④）

- **② install 真装机成功路径未在 verify 触发 —— 会成为 T10 的真问题（中高）**。verify 走的是 `service.js:302` 的同 requestId 短路 + 合成载荷，`runInstall` 从未执行。真机要过 `ctx.get('subprocess')`／`resolveCliEntry`／可能被 `desktopProfiles` 判成 `desktop` 走 `desktopPnpm`（T1 §K.2 未证实）——这些都在**更新包执行层**，T7 接线无从断言，失败症状只会是 `install-failed`/`recovery-required`。**但有一条 T7 侧的正面发现**：自有 reader 让装机后 `env.blockedReason` 落 `pending-restart`（而非上游 `readInstalledReal` 的 `installation-changed`），恰是 `service.js:279` 放行的值 ⇒ 若仍用上游 reader，装机后复查会**直接判 install-failed**。结论：②是 T10 的必测项，不是 T7 的缺陷；T10 预案里要写清「install 失败先看更新包 job 落盘，而非本仓接线」。
- **③ `resolveProfileDir` 四级判定未断言 —— 真机风险：低（本次已用真盘探针补证）**。第③级在本机**实测命中且正确**。残余条件风险：若将来 `desktop` 也改成 Junction 指向同一份源码，第③级按 `readdirSync(...).sort()` 取名，`desktop < web` ⇒ 从 web 侧加载的实例会被静默认领到 `profiles\desktop`（错范围）。今天 desktop 是真 npm 安装故不触发；建议加一条「该 profile 的 `package.json` 依赖确含本包」或优先用运行 profile 名做判据。
- **④ 同一实例重复 `start()` 建新 scheduler 不停旧的 —— 真机风险：低（不阻断 T10）**。全仓 `update.start()` 唯一调用点 `index.ts:69`；热重载换的是**新实例**，且宿主一旦「先 apply 新实例」新实例会走让位分支（`index.ts:59-64` 早退）⇒ **根本不建第二个 scheduler**，双份触发缺一条成立路径。真正要修的是一对**窄窗口句柄泄漏**（见整改 1）：`start()`（`:129-138`）与 `apply()`（`:139-150`）都直接覆盖 `period` 槽位而不先释放——若面板的 `meta.update.set` 抢在 `store.load()` 落定之前到达（亚秒竞态），旧句柄永不释放 ⇒ 周期检查双份。

## 未覆盖与假绿风险

2. **非法值 `bad-request` 无断言**：`update-host.ts` 无该路径用例（静态可读、风险低，但属未覆盖）。
3. **假绿提示**：verify `beforeEach` 复位 `__resetSharedUpdateReaderForTests` 是**测试隔离**手段，绕开了 `host.js:93` 单例键的跨实例语义；生产只有一处调用点故无碍，但将来若真出现同进程双实例，这层复位会掩盖问题。
4. **reader 两处与上游非等价**（只影响极端态诊断，非阻断）：invalid `profileName` 早退时上游回**原名**（`reader.js:118`），本仓回 `null`（`update-reader.ts:132-136` 未赋值）；`validPackage` 上游还会 `realpath` 入口后复判 `inside`（`reader.js:57-63`），本仓只判 `resolve+isFile`（`:87-94`）。另：`installationKey` 口径自持（不含 LOCK_FILES）——进程内 check→install 同源自洽（`service.js:252/309/325`）故安全。
5. **信封语义提醒（交 T8）**：本仓失败信封无顶层 `errorKind`，同名 token 只能在 `error.code` 读（原载荷在 `details.update`）；未知 token 折 `internal`（包已先折成 `check-failed`/`internal`，实际不可达）。①「客户端消费侧分支不存在」故属 T8 待验，不是 T7 缺陷。
6. **⑤（包内复查窗口走包自己的 `now` 端口）**：verify 已把 `now: clock.now` 与假时钟同源注入（`update-host.ts:157`），假时钟真能控制该窗口 ⇒ 非假绿点；生产用真 `Date.now`，无风险。
