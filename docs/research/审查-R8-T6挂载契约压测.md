# 审查 R8：T6「更新中心挂载点契约」压测（T8 施工图可用性）

审查对象：`panel.ts` +19/−2、`data/config.ts` +4/−0（`git diff` 实读）。方法：只读点名文件 + 只读宿主取证（DSH `app.asar` 内解出 `dsh-client-ui-settings-general` / `dsh-client-ui-renderer` 两个模块文本，仅读不写）。
结论一句话：**机制是对的、时序断言为真，但"如何挂"这份施工图缺 2 个高位守卫，照抄会写出假死/漏接的代码。**

## 时序断言核实

- 循环 vs 注册：`src/client/index.ts:53-63`（`for (const f of FEATURES) { … for (const s of f.slots ?? []) stopFeatures.push(s.mount(featureCtx)) }`）确实在 `:115-122`（`ctx.slots.inject('settings.section', () => ctx.slots.register({…}))`）**之前**，且在同一个同步 `apply()` 内。**断言为真**。
- 面板创建点：**slot 渲染时**——`index.ts:65-92` 的 `FleetSettingsTab` 里 `React.useEffect(() => { … panel = FleetPanel(ctx)（:73）… mount.appendChild(panel)（:74）}, [])`。它只在「设置对话框打开 + `activeId` 命中 `dsh-im-companion` 这一 entry」时才被渲染。
- 因此真实保证比 T6 写的更强：**监听注册 → slot entry 注册 → 面板创建**是同一插件的程序序，正常启动下"面板早于监听"不可能发生。T6 的推理（"循环早于 slots.register"）只是这一保证的弱化表述。
- 广播时 root **确实未入文档**：`:180` 派发，`:74` 才 appendChild。⇒ `detail.host` 是 detached 元素（见下"陷阱"）。

## 漏接路径清单

| 场景 | 会漏？ | 依据 |
| --- | --- | --- |
| 正常启动：加载 → 开设置 → 选 IM 段 | **不漏** | `index.ts:53-63` 早于 `:115-122`，渲染只能发生在 entry 注册之后 |
| 热重载 / 插件重载，且设置正开着 IM 段 | **会漏** | 旧实例 `stop()` 已摘监听、旧面板卸载的 null 也可能无人接；新实例 apply 与 React 因 registry 变化的重挂载无严格先后 ⇒ 事件可能落在空窗。症状：面板空白直到用户重开 |
| 面板重挂载（关对话框 / 切段再切回） | 不漏，但 `{host}` 会**多次到达** | `index.ts:82-89` cleanup 每次 `__afDispose()`；新 mount 再 `FleetPanel()`。⇒ 必须幂等 |
| 事件顺序倒置（host→null） | **会中招** | 正常序是 null→host（React cleanup 先于新 effect），但 HMR 下可能倒置；T6 只说"可自愈"，**没说守卫条件**——"null 即全清"会把刚挂好的新面板一起清掉 |
| 同一 apply 内的 feature 卸载重装 | 会漏 | `stop()` 摘监听期间到达的事件无人接 |
| 双窗口 / 双 profile | 不漏 | 各自独立页面；但 `#imc-update-center` 是全局 id，多实例时 `querySelector` 只给第一个 |

**陷阱（不是漏接，是使用姿势）**：`{host}` 到达时元素不在文档里 ⇒ 任何 `getBoundingClientRect` / `offsetHeight` / `scrollIntoView` / `focus` / `IntersectionObserver.observe` 都退化为 0 或无效。插入 DOM 可以立刻做，**测量必须延到 rAF 或 attach 之后**。

## 容器与布局影响

- CSS 规则：全仓（含 `lib/client.js`、`preview.html`、`prototypes/`）搜 `.uc-host` / `#imc-update-center`，只有两处命中且都是**元素创建本身**（`src/client/components/panel.ts:177`、构建产物 `lib/client.js:3962-3963`）。**零 CSS 规则匹配，T6 的"无样式"说法为真**。
- `.af-root`（`theme.ts:24-38`）**没有 display 声明** ⇒ 普通块流（block flow），子元素按序纵向堆叠；`.af-body` 全仓无样式规则（grep 仅命中一篇研究文档）。⇒ 插在 `.af-body` 与 `.af-promo` 之间的空 div（无 margin、无内容 ⇒ 高 0）**像素级零变化**；`.af-promo{margin-top:12px}`（`first-view-styles.ts:36`）相邻关系不变。
- 宿主侧：设置面板内容区 `.options{flex:1;min-height:0;padding:0 24px 24px;overflow-y:auto}`，外框 `.panel{height:min(800px,100vh-48px);overflow:hidden}` ⇒ **面板长高只是内部滚动，不会挤压/错位**。
- 结论：**不需要为"防错位"加样式**；但 T8 必须自备内容样式（`installFeatureStyles('update-center', css)`，类前缀 `update-center-*`），且**不要改 `.uc-host` 自身的定位/间距**——那是 A1 的契约面。

## 隐藏不卸载的兜底（§K.5 → 已证实）

宿主码（`app.asar:/node_modules/@deepseek-ai/dsh-client-ui-settings-general/lib/client.js`）：
- `:289` `open && jsx(SettingsPanel, {…})` —— 设置对话框关闭 ⇒ 整个内容区**卸载**；
- `:197` `active !== void 0 && renderSlot("settings.section", {…}, { only: active })` —— 只渲染当前段；切到别的段 ⇒ IM 段**卸载**（不是 `display:none` 藏起来）；
- `app.asar:/node_modules/@deepseek-ai/dsh-client-ui-renderer/lib/client.js:867` `if (opts?.only !== void 0) list = list.filter(item => item.id === opts.only)` —— 非激活 entry 根本不渲染，**无 keep-alive**。

⇒ **结论：settings 区块"隐藏"= React 卸载 ⇒ `__afDispose` 跑 ⇒ `{host:null}` 必发**（`panel.ts:214-215`）。§K.5 可以升级为"已证实（针对段级隐藏）"。仍存的唯一"可见而挂载"情形是**窗口/tab 级不可见**（最小化、切标签）——此时面板保持挂载，本仓 src 内 `visibilitychange`/`IntersectionObserver`/`visibilityState` 零命中（grep 实查）。T6 原文的"不能只靠 null 事件回收"应改写成：**null 事件可信，但它不是唯一清理点（stop()、热重载、顺序倒置都需自兜底）**。

## 改写后的挂载契约（T8 直接照抄）

1. `features/index.ts`：`import { feature as updateCenter } from './update-center/manifest'` + 数组加一项（`order` 取现值之后，如 24）。
2. manifest：`slots: [{ target: 'settings.section', mount: (ctx) => mountUpdateCenter(ctx) }]`；`installStyles: () => installFeatureStyles('update-center', CSS)`。**`mount()` 里只做三件事：摘旧、注册监听、adopt 兜底**——绝不在这里碰 `ctx.meta` / `ctx.rpc`。
3. 注册（照抄 `src/features/fleet-radar/view.ts:219-236` 样板）：
   ```ts
   const onHost = (e: Event): void => {
     const host = (e as CustomEvent<{ host: HTMLElement | null }>)?.detail?.host ?? null
     detach()                       // 先全拆：清 1s 表 / 退订 / 清容器 DOM / 摘文档级监听
     if (host) attach(host)
     else { const alive = document.querySelector<HTMLElement>('#imc-update-center.uc-host'); if (alive) attach(alive) }  // 兜住顺序倒置与热重载
   }
   window.addEventListener(UPDATE_CENTER_HOST_EVENT, onHost as EventListener)
   ```
4. `mount()` 内、`addEventListener` 之后立刻做一次同步 adopt：`const cur = document.querySelector<HTMLElement>('#imc-update-center.uc-host'); if (cur) attach(cur)`（覆盖"面板已存在才装载 feature"的空窗，成本 ~2 行，且只用已公布的 id+class，不碰 A1 私有约定）。
5. `attach(host)`：把 T8 自有根节点塞进 host（`host.replaceChildren(root)`），**再做**一次 `void ctx.rpc?.call('imc.updateStatus', {})` 重拉状态（防跨挂载显示陈旧 `installing`）；测量类操作放 `requestAnimationFrame`。
6. `detach()`：清 1s 表、退订、`host.replaceChildren()`、断掉与旧 host 绑定的一切；**幂等**（可重复调用）。
7. `mount()` 返回的 `stop()`：`removeEventListener(UPDATE_CENTER_HOST_EVENT, onHost as EventListener)` + `detach()`（插件卸载时面板可能仍挂载，必须双保险）。
8. 传给 `removeEventListener` 的必须是**同一个函数引用**（闭包持有的 `onHost`），且捕获参数一致（默认即可）。

## 与轮询清理约束的接缝

- T4 §A「挂载读一次 + 仅 `installing`/`verifying` 期 1 s 表、离开即清、不得常开」**本挂载点足以支撑**：段级隐藏已证实是卸载 ⇒ `{host:null}` ⇒ `detach()` 清表，天然满足"离开即清"；窗口最小化这类"挂载但不可见"不触发，但 1 s 表本身只存活于安装期（≤ `installTimeoutMs`），可接受。
- 两点必须补：① **null 事件不是唯一清理点**——`stop()`（热重载 / 插件卸载）也要清表，否则跨代叠加；② **重挂载必须重拉 `imc.updateStatus`**，否则用户关窗再开只会看到永久"安装中"。
- 一处 API 落差：T4 §137 的"一律走 `ctx.interval`、禁裸 `setInterval`"在**宿主侧**成立（`src/host/update-schedule.ts:13`），但 client 的 `FeatureCtx`（`src/features/protocol.ts:22-32`）**没有 `interval`**；客户端先例是裸 `setInterval` + 手动清（`src/client/data/connection-stream.ts:70,92`、`components/connect-flow.ts:58-65`）。⇒ T8 用 `window.setInterval` + 双路清理，并在提审材料里明确这条例外，别去找不存在的 `ctx.interval`。

## 评分与结论

**可用性评分：74 / 100。裁决：需修正后照抄。**

- 加分项：事件名单点真相、容器位置、时序断言（且真实保证强于其表述）**全部核实为真**；null 事件在段级隐藏路径上**必发**（§K.5 已由宿主码证实）；零 CSS 污染、零布局风险。
- 扣分项：施工图有 2 个高位坑未提示（`mount()` 内同步读 `ctx.meta` 会抛并被静默吞掉 ⇒ 特性假死；`installStyles`/adopt 兜底缺失 ⇒ 热重载/顺序倒置窗口漏接），以及"先拆再挂"的守卫条件、"重挂载重拉状态"未写明。

**修正项（按严重度）**：

1. **P0** `mount()` 内禁止同步触碰 `ctx.meta`/`ctx.rpc`：`FeatureCtx.meta` 是 getter，`createMetaStore` 尚未 resolve 时**抛错**（`index.ts:24-28,33-36`），而 `index.ts:60-62` 的 `catch{}` 会**静默吞掉** ⇒ 监听不注册、特性假死且无日志。读取一律放进 `{host}` 回调里并 try/catch。
2. **P0** `mount()` 末尾同步 adopt 已存在的 `#imc-update-center.uc-host`，并在 null 处理后复查 live 容器（关掉"面板已存在才装载"与"host→null 顺序倒置"两个窗口）。
3. **P1** `{host}` 处理必须"先全拆再挂"且幂等（含清 1s 表、退订、清旧容器 DOM）；`stop()` 也要 `detach()`。
4. **P1** 每次 attach 后重拉 `imc.updateStatus`（跨挂载状态同步）。
5. **P2** detached 容器不做测量/滚动/聚焦，改用 rAF。
6. **P2** `detail` 需显式断言 `CustomEvent<{ host: HTMLElement | null }>`；`removeEventListener` 用同一函数引用（照 `fleet-radar/view.ts` 抄）。
7. **P2** 1 s 表用 `window.setInterval` + 双路清理，并在提审材料说明这是 T4 §137 宿主侧纪律的客户端例外。
