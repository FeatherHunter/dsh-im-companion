## 1. web profile 安装态与切换后果

现状（`C:\Users\辰辰洋洋\.dsh\profiles\web\package.json`）：
`"dsh-im-companion": "link:D:/dsh-plugin/dsh-im-companion"`，且 `dsh.profile.bundles` 共 17 项含 `dsh-im-companion`。
`Get-Item ...\web\node_modules\dsh-im-companion -Force` → `LinkType=Junction, Target={D:\dsh-plugin\dsh-im-companion}`。
`pnpm-lock.yaml:29-31` → `specifier: link:D:/dsh-plugin/dsh-im-companion` / `version: link:...`。

**改版本号安装会精确改动**：① `package.json` 那一行变 `"0.1.8"`；② `node_modules\dsh-im-companion` 由 Junction 变成真实目录（pnpm 按 `nodeLinker: hoisted` 平铺）；③ 新增 `node_modules\dsh-plugin-update`（本仓成为它的运行时依赖）；④ `pnpm-lock.yaml` 的 specifier/version 同步；⑤ `dsh.profile.bundles` **不变**（`dsh.bundle` 声明仍在，`plugin-Ddi42qoW.js:35-77` 按已装态对账）。

**宿主何时加载（会不会打断用户）**：
- 启动时一次性。`profile-boot-Dk-7KqJc.js:76-80` 按 `dsh.profile.bundles` 顺序把层叠成树并挂载；bundle 目录在装载时由 `resolveBundleDir(NAME, pkg, INSTALL_ANCHOR, profileDir)` 解析（`plugin-Ddi42qoW.js:28`）。
- 启动后**只** watch 用户补丁文件：`profile-boot-Dk-7KqJc.js:321-338`，`patchReload==='live'` 时装 `@deepseek-ai/cordis-plugin-hmr` 并 `watchUserPatches(... patchPath / homePatchPath())`。**不 watch `package.json`、不 watch `node_modules`**。旁证：`C:\Users\辰辰洋洋\AppData\Roaming\DSH Desktop\profile-patch-heal-cache.json` 只有 `profiles\web\cordis.patch.yml` 一条。
- 运行中的宿主就是 **web profile**：43120 监听进程 PID 31252 = `DSH Desktop.exe`（Electron node utility）；`AppData\Roaming\DSH Desktop\host-commands\web\bin\dsh.cmd` 内写死 `DSH_DESKTOP_DEFAULT_PROFILE=web` + `DSH_HOME=...\.dsh`。
- ⇒ 改 `package.json` + 装包**不会**让运行中的宿主加载到/丢失本插件；页面不断、面板继续用**旧模块**；要生效必须**重启 web 宿主**（=打断用户当前会话）。

**更新包在切换后的读数（关键风险）**：`dist\reader.js:144` 每次读盘重算
`sourceInstall = !registrySpec(deps[target]) || !inside(profileDir\node_modules, realpath(installedDir))`。
实测 `registrySpec('link:D:/dsh-plugin/dsh-im-companion')` → `false` ⇒ 今天必为 `source-install`（`reader.js:160`）。
切成版本号后该项变 `false`，但 `reader.js:147-152` 的
`sameLoadedPackage = loaded.directory === installed.directory && 版本相等` 会变成 false：
跑着的插件 realpath 仍是 `D:\dsh-plugin\dsh-im-companion`，而装的在 `profiles\web\node_modules\...`
⇒ `blockedReason = installation-changed`，**不会**自愈成 T10 期望的 `pending-restart`。
若重启后更新包改从 profile 的 `node_modules` 解析，则 `containingPackage()` 走不上去（实测 `null`）→ `host.js:70-73` 算不出 `runningVersion` → 抛 `unknown-profile`。
⇒ **切换后五态验收可能直接卡死**，需 T7 期先探明（见 §5 预警 1）。

## 5. 对抗式路线核查：最可能失败的 3 种方式

**失败 1 · 切换后更新系统「认不出自己」，五态验收卡死。** 见 §1 末段（`installation-changed` / `unknown-profile`）。
早期预警（已实测，可复制）：
```powershell
$u="$env:USERPROFILE\.dsh\profiles\web\node_modules\dsh-plugin-update\dist"
node -e "const {pathToFileURL}=require('node:url');import(pathToFileURL(process.argv[1]).href).then(async m=>console.log('WALKUP='+JSON.stringify(await m.containingPackage(process.argv[2],'dsh-im-companion'))))" "$u\reader.js" "$u\host.js"
```
实测输出 `WALKUP=null` ⇒ 更新包一旦从 profile 的 `node_modules` 解析，`runningVersion` 就是 `null`。
**更便宜的替代**：T7 接线时**永远显式传** `readerOverrides: { runningVersion, profileDir, profileName }`（`host.js:88-92、216-236` 是口子），可消掉 `unknown-profile`；`installation-changed` 要治只能改上游 `dsh-plugin-update` 的 `containingPackage`（跨仓 ⇒ owner 决策）。

**失败 2 · 镜像站落后，手工/兜底安装拿不到 0.1.8。** 证据见 §2（镜像 latest=0.1.6，官方=0.1.7）。
预警：发布后立刻 `npm view dsh-im-companion dist-tags --registry=https://registry.npmmirror.com` 看是否跟进。
**更便宜的替代**：更新包自动路径自带 `--registry=https://registry.npmjs.org/`（`dist\commands.js:3,52`），不受镜像影响；只有**人手敲 `pnpm add`** 才会踩 ⇒ 任何写入文档/面板的手工命令都必须保留 `--registry` 尾巴。

## 回滚手册（可复制粘贴）

> **前提 A（缺则命令必失败）：执行任何切换前，必须先停掉 web 宿主。** 运行中的宿主占着 `node_modules\dsh-im-companion` 那个 Junction，`dsh plugin add` 会报 `EPERM/EBUSY`（原正文只在 A 的「失败处置」里提过一次，此处升为总前提）。
> **前提 B（人工步，agent 不代做）：停宿主与重启都由项目负责人本人手动完成**——agent 不代按、不代重启（依据 `docs/research/更新系统-T4决策档案.md` §5.3「由 owner 亲自关闭并重开 DSH Desktop」；军规：**无必要绝不让用户重启 DSH**）。重启前不做任何 `cordis.patch.yml` 免重启实验（未证实，且该文件历史坏过）。
> 前提：`dsh` 已在本机 PATH（`Get-Command dsh` → `…\AppData\Roaming\DSH Desktop\host-commands\web\bin\dsh.cmd`）。
> 所有命令都**必须**带 `--registry=https://registry.npmjs.org/`；直跑 `pnpm add` 会走镜像站（latest 只到 0.1.6）。
> 改前务必备份：`Copy-Item "C:\Users\辰辰洋洋\.dsh\profiles\web\package.json" "C:\Users\辰辰洋洋\.dsh\profiles\web\package.json.bak-before-t9-$(Get-Date -f yyyyMMdd-HHmm)" -Force`
