# 更新系统 · 更新包升 0.2.0 + 发布侧自动跟随（#99）

> 起因（用户指示 2026-09-30）：上游 `dsh-plugin-update` 已发 **0.2.0**（独立仓 `FeatherHunter/dsh-plugin-update`，npm `dist-tags.latest = 0.2.0`），要求：① 我们的更新系统改用新包；② **尽量解耦**；③ **每次构建要发布的版本时检测最新 npm 包并依赖它发布**，让用户装到的插件一定带最新更新系统。
>
> 本文是这次改动的**唯一取证档案**：0.2.0 真身读数、删了什么、发布侧三条闸门、验证读数。引用包内行号一律以**发布产物 `dist/*.js`** 为准（0.2.0 基线 `node_modules/dsh-plugin-update@0.2.0`，tarball 实测解包）。

## 1. 0.2.0 与 0.1.1 的真身差异（逐条实测）

| 面 | 0.1.1（旧接线的前提） | 0.2.0（实测） |
|---|---|---|
| 目标包定位 | 只有 `containingPackage(import.meta.url, 包名)`——起点是**更新包自己所在的目录**，按版本号装进 profile 后目标包是兄弟目录 ⇒ 恒 `unknown-profile` | `resolveTargetPackage(包名)` 四步：`createRequire` 清单直解 → 入口反查 → 沿 `node_modules` 步行 → 自锚定兜底（`dist/reader.js:49-90`）；**导出里多了它**（18 个导出 vs 0.1.1 的 17 个，其余逐名相同） |
| 使用范围目录 | 无参可给，只能靠注入 | 从目标包实装路径反推（`dist/host.js:73-90` 的 `tryInferProfileDir`），失败才 `unknown-profile`（`:111`） |
| 安装出口 | `desktopPnpm` / `dsh plugin` 两条 | **三条**：第三方 Desktop `desktopPnpm.runPlugin`、官方桌面 `pluginManager.installBundle`、普通宿主 `dsh plugin --profile … add`（`detectEnvironmentKind`，`dist/host.js:31-46`） |
| 错误码表 | 13 个 known，表外折叠 `check-failed` + `errorKind: internal` | **逐字相同**（`dist/host.js:169-188`） |
| 快照六字段 / 三个电话名 / `receipt` 语义 / 八种 `blockedReason` | — | **一字未变**（README §2 表 / §5.1 / §5.2 与 0.1.1 对照） |
| `.d.ts` | 一个都不发（只发 `dist/*.js`） | **仍然不发** ⇒ 本仓自持声明继续必要 |
| 客户端取值入口 | `derive-client-values.mjs`（要 esbuild） | 同工具仍在，但 `dist/client.js` 可直接按**文件 URL** 载入（`buildClientPhoneNames` / `CLIENT_POLL.defaultMs/minMs`）⇒ 不需要 esbuild |

**结论**：0.2.0 把我们 0.1.x 时代被迫自写的东西**原生接管**了：`unknown-profile` 的根因、`installation-changed` 的假阳性（README 排错第 12 条明说 0.1.x 依赖形态下恒失败）都不再需要集成方兜。

## 2. 本仓改了什么（解耦账）

**删除（整体，不是改写）**
- `src/host/update-reader.ts`（194 行）：自持的清单/安装/合法性/安装指纹读取器 —— 0.2.0 的 `readInstalledReal`（`dist/reader.js:161-224`）逐项对应。
- `src/host/update-paths.ts`（92 行）：自持的包根/运行版本/使用范围目录解析 —— 0.2.0 的 `resolveTargetPackage` + `tryInferProfileDir` 接管。
- `UPDATE_ERROR_CODES`（13 条恒等映射表）：包已归一原因码，本仓改为**原样透传**（不自造第二套词表）。

**改动**
- `src/host/update.ts`（224 行）：装配只剩 `{ ctx, logCtx, readerOverrides: { homeDir } }` + 配置三件套；信封、`autoCheck` 运行期状态、受管定时器调度器**逐字保留**。`homeDir` 是**取值**不是实现（本仓 `dshHome` 可被插件配置覆盖，而包的默认只看 `DSH_HOME`/家目录），保留它才能保证更新落盘与本仓 `meta.json` 同源。
- `src/host/dsh-plugin-update.d.ts`（44 行）：声明面从 5 个成员收缩到 **2 个**（`createHostUpdate` / 测试用 `__resetSharedUpdateReaderForTests`）；`registrySpec` / `profileNameValid` / `detectEnvironmentKind` 不再被本仓使用。
- `src/features/update-center/constants.ts`：五个派生常量改为从新文件 `derived.ts` 再导出；本仓自有常量（桥载体 / RPC 超时 / 版本说明源）原地不动。

**新增**
- `src/features/update-center/derived.ts`：**生成物**（构建期派生，人手不改）。
- `scripts/gen-update-constants.mjs`：从**已安装的**更新包派生五个常量；电话名宿主侧（包根 `buildPhoneNames`）与客户端侧（`dist/client.js` 的 `buildClientPhoneNames`）**交叉核对**，不一致直接报错；`--write` 写盘，缺省即比对模式（不一致 exit 1）。
- `scripts/sync-update-pkg.mjs`：查**官方源** `latest` → 与本仓 pin 比对；`--apply` 则装 latest（`--save-exact`）+ 重生成常量。
- `package.json` scripts：`gen:update-constants` / `check:update-pkg` / `sync:update-pkg`；`build` 前置生成器比对。
- `scripts/wizard-release.sh` 阶段 1：发布前跑 `sync-update-pkg.mjs`，落后即 ✗ 并打印修法（`WIZARD_SKIP_UPDATE_PKG=1` 可显式跳过）。

**发布侧三条闸门（回答「用户一定拿到最新更新包」）**
1. `npm run build`（发布必跑）→ 生成器比对：`derived.ts` 必须与**已安装的**包一致 ⇒ 改了 pin 忘重生成 = 构建直接红。
2. `npm run check:update-pkg` → 官方源 `latest` vs 本仓 pin；落后 exit 1（`node_modules` 与 pin 不一致也 exit 1）。
3. `wizard-release.sh` 阶段 1 内置第 2 条 ⇒ **发布那一刻 pin 必然等于上游 latest**。
